###### 摘要

人们越来越期望大型语言模型（LLM）智能体能够在长期交互中运行，其中必须保存和调用过去对话的信息以支持未来的任务。然而，随着交互的积累，记忆存储会无限制地增长，并充满冗余条目，这些条目会挤出最有用的证据，从而增加存储成本并降低检索效率。此外，这对于具有硬内存预算的资源受限平台尤其有限制，促使我们制定“存储预算内存管理”，即将已构建的内存存储保持在固定预算内，同时保留对未来交互有用的信息的任务。为此，我们随后提出了 MemRefine，这是一个 LLM 指导的框架，由于表面相似性很难反映事实价值，因此仅使用相似性来提出候选对，并推迟删除、合并和保留基于事实内容的 LLM 法官的决定，迭代直到满足预算。在多个内存框架和长期对话基准中，MemRefine 始终满足目标预算，同时在预算紧张的情况下保持下游性能并超越基于规则的基线。

## 1 简介

人们越来越期望大型语言模型（LLM）智能体能够在长期交互中运行，其中有用的信息可能分布在过去对话、会话或事件的扩展序列中（[Zhong et al., 2024](https://arxiv.org/html/2606.13177#bib.bib4); [Maharana et al., 2024](https://arxiv.org/html/2606.13177#bib.bib17); [Xu et al., 2025](https://arxiv.org/html/2606.13177#bib.bib7))。为了支持这种交互，最近的智能体框架为 LLM 配备了持久内存存储，记录交互历史并将其作为未来任务的证据（[Packer et al., 2023](https://arxiv.org/html/2606.13177#bib.bib6); [Zhong et al., 2024](https://arxiv.org/html/2606.13177#bib.bib4); [Xu et al., 2025](https://arxiv.org/html/2606.13177#bib.bib7)；[Chhikara 等人，2025](https://arxiv.org/html/2606.13177#bib.bib19)；[Wu 等人，2025](https://arxiv.org/html/2606.13177#bib.bib18))。

然而，持久内存会带来存储效率问题，并且随着时间的推移，问题会更加严重。随着智能体继续交互，记忆存储无限增长，并逐渐填充与其他地方已经捕获的信息重叠或重复的条目（[Zhong et al., 2024](https://arxiv.org/html/2606.13177#bib.bib4); [Xu et al., 2025](https://arxiv.org/html/2606.13177#bib.bib7); [Fang et al., 2025](https://arxiv.org/html/2606.13177#bib.bib11); [Liu et al., 2026](https://arxiv.org/html/2606.13177#bib.bib10))，这既会增加存储成本（在资源受限的平台上，这是一个特别严重的问题，例如内存预算受到严格限制的设备上部署），也会降低检索性能，因为智能体可能会出现接近重复或低价值的条目。受此启发，我们引入了“存储预算内存管理”的新任务，其中智能体记忆需要持续保持在固定预算内，同时保留对未来交互仍然有用的信息。

然而，现有的压缩方法并不针对此设置。会话级摘要（[Wang et al., 2025](https://arxiv.org/html/2606.13177#bib.bib8)；[Chen et al., 2025](https://arxiv.org/html/2606.13177#bib.bib9)）在原始对话历史记录进入内存之前对其进行压缩，而不是最终的存储、提示或检索上下文压缩（[Jiang et al., 2023](https://arxiv.org/html/2606.13177#bib.bib13); [Xu et al., 2024](https://arxiv.org/html/2606.13177#bib.bib12); [Jiang et al., 2024](https://arxiv.org/html/2606.13177#bib.bib14)) 在推理时对提供给 LLM 的证据进行操作，并进行基于结构的图剪枝（[Brin 和 Page, 1998](https://arxiv.org/html/2606.13177#bib.bib16)) 依赖于诸如中心性之类的标准，这些标准无法捕获条目是否实际上是冗余的、互补的或不同的。因此，这些方法都没有在推理条目的实际内容的同时将已经构建的内存存储联合减少到目标存储预算。

为了解决这个问题，我们引入了“构建后内存压缩”，其中已构建的内存存储被减少到目标存储预算，同时保留对下游任务有用的信息，并提出了 MemRefine，一个 LLM 引导的框架，该框架将该任务实例化为在内存构建之后和检索之前插入的通用模块，而无需修改主机内存管道。核心观点是，虽然表面水平的相似性对于呈现相关记忆的候选对很有用，但仅相似性太弱而无法决定它们的命运，因为两个文本相似的条目可能携带可以删除的冗余事实​​、应该合并的互补事实或都需要保留的不同事实。受此启发，MemRefine 使用相似性来提出候选对，但将压缩决策本身推迟给法学硕士法官，该法官检查每对并根据事实内容而不是表面措辞决定是否应该删除、合并或保留，直到内存存储符合目标存储预算。

我们在两个具有不同表示形式的代表性内存框架上验证了 MemRefine，即链接结构化笔记的 A-MEM 式图形内存（[Xu et al., 2025](https://arxiv.org/html/2606.13177#bib.bib7)）和通过摄取和更新过程构建条目的 Mem0 管道（[Chhikara et al., 2025](https://arxiv.org/html/2606.13177#bib.bib19)），跨多个评估LLM 的评判和对话长度基于标准和扩展的 LoCoMo 风格基准（[Maharana et al., 2024](https://arxiv.org/html/2606.13177#bib.bib17)）。在各种设置中，MemRefine 始终满足目标存储预算，同时在适度压缩下保留下游性能，并且在更严格的预算下优雅地降级而不是崩溃。此外，与用固定相似性或图结构启发法取代 LLM 判断的基于规则的基线相比，MemRefine 始终更加稳健，支持我们的假设，即压缩决策受益于 LLM 指导的事实判断，即使仅相似性足以用于候选人选择。

## 2 相关工作

##### LLM 智能体的长期记忆

长期记忆已成为对话系统和法学硕士智能体的核心组成部分，这些智能体对在扩展交互中积累的信息进行操作。关于长期和多会话对话的早期工作表明，会话智能体需要存储、更新和检索先前会话中的信息，以保持随时间的一致性（[Xu et al., 2022](https://arxiv.org/html/2606.13177#bib.bib1)；[Bae et al., 2022](https://arxiv.org/html/2606.13177#bib.bib2)；[Jang et al., 2023](https://arxiv.org/html/2606.13177#bib.bib3))。最近的工作为 LLM 智能体开发了外部存储系统，包括用户级存储库（[Zhong et al., 2024](https://arxiv.org/html/2606.13177#bib.bib4)）、显式读写存储模块（[Modarressi et al., 2023](https://arxiv.org/html/2606.13177#bib.bib5)）、虚拟上下文管理（[Packer et al., 2023](https://arxiv.org/html/2606.13177#bib.bib6))、结构化笔记图([Xu et al., 2025](https://arxiv.org/html/2606.13177#bib.bib7))和智能体的通用记忆层([Chhikara et al., 2025](https://arxiv.org/html/2606.13177#bib.bib19))，以及评估此类系统是否可以回忆长期历史信息的基准（[Maharana 等人，2024](https://arxiv.org/html/2606.13177#bib.bib17)；[Wu 等人，2025](https://arxiv.org/html/2606.13177#bib.bib18)）。然而，这些努力主要集中在“增长”记忆上，即随着交互的积累，如何添加和调用新信息，而在存储预算下“缩小”已构建的存储的逆问题基本上没有得到解决。相比之下，我们对待施工后存储 将缩减作为一项独立任务，压缩现有内存存储以适应目标预算，同时保持主机内存框架不变。

##### 内存和上下文压缩

降低存储或处理长期信息的成本已经在相关但不同的环境中进行了研究。会话级记忆摘要在对话历史进入内存之前将其压缩为紧凑的摘要，例如，通过长期对话记忆的递归摘要（[Wang et al., 2025](https://arxiv.org/html/2606.13177#bib.bib8)）或压缩记忆增强对话生成（[Chen et al., 2025](https://arxiv.org/html/2606.13177#bib.bib9)）。与此同时，推理时间上下文压缩反而减少了提供给 LLM 的证据或提示，而不是底层存储，包括 RECOMP 用于检索文档（[Xu et al., 2024](https://arxiv.org/html/2606.13177#bib.bib12)），LLMLingua 和 LongLLMLingua 用于长上下文提示（[Jiang et al., 2023](https://arxiv.org/html/2606.13177#bib.bib13); [Jiang et al., 2024](https://arxiv.org/html/2606.13177#bib.bib14)）。基于结构的缩减通过中心性或连接性等标准离线缩小内存图 （[Brin and Page, 1998](https://arxiv.org/html/2606.13177#bib.bib16); [Wang et al., 2026](https://arxiv.org/html/2606.13177#bib.bib15))，而最近的智能体记忆框架通过过滤、整合或与构建管道交错的轻量级更新来提高内存效率([Fang et al., 2025](https://arxiv.org/html/2606.13177#bib.bib11); [Liu等人， 2026](https://arxiv.org/html/2606.13177#bib.bib10)).

然而，这些方法都没有将*通过推理其条目的事实内容将已构建的内存存储减少到固定的存储预算*作为明确的目标：摘要抢占内存而不是缩小内存，上下文压缩涉及推理时间提示而不是存储，基于结构或基于更新的方法要么依赖于对内容不敏感的标准，要么保持与构建管道的耦合。相比之下，我们通过直接将现有内存存储压缩到目标存储预算来填补这一空白，对语义相关的条目应用LLM引导的判断来决定每对是否携带要删除的冗余事实​​、要合并的互补事实或要保留的不同事实，同时保持与底层内存构建和检索管道的解耦。

## 3 方法

我们提出了 MemRefine，一个 LLM 指导的框架，它将已经构建的智能体记忆存储压缩到目标存储预算，同时保留对未来交互有用的信息。我们首先将存储预算内存管理形式化为与查询无关的内存压缩上的预算受限的最大最小程序，并引入 MemRefine，这是一个 LLM 引导的成对细化过程，可对其进行操作。

### 3.2 内存优化

##### 成对细化。

上述每对替代项的直接替代方案是独立地为每个内存条目分配重要性分数，并删除低分数条目，直到满足预算。然而，这未能捕捉到激发方程[1](https://arxiv.org/html/2606.13177#S3.E1“在存储预算内存管理中。‣ 3.1 问题表述‣ 3 方法‣ MemRefine：用于长期智能体记忆的 LLM 引导压缩”）的核心属性：内存条目的值是*相关的*而不是独立的，因为条目可能在孤立时显得边缘，但在组合时却变得不可或缺与另一个；相反，条目可能看起来很有价值，但可以安全地删除，因为相同的事实已经存储在M′M^{\prime}.中的其他位置，这两种故障模式在任何每个条目标准（例如，嵌入规范、新近度或图形中心性）下看起来都是相同的，因此单条目评分无法判断编辑何时删除了其他地方没有冗余覆盖的事实。为了解决这个问题，MemRefine 对语义相关的内存条目“对”进行操作：对于任何对 (u,v)(u,v)，联合内容会彻底分解为冗余情况（一个条目的内容已被另一个条目覆盖）、一个补充情况（每个条目贡献另一个条目缺少的内容）和一个不同的情况（两个条目断言不相关的事实），这直接导致一个 *删除*–*合并*–*保留* 操作空间与由ℱ⁡(M0){\mathcal{F}}(M\_{0}). 此外，MemRefine 通过迭代候选对并为每对选择一个操作直到满足预算或没有未解决的候选者来实现这一点；算法 [1](https://arxiv.org/html/2606.13177#alg1“算法 1 ‣ 成对优化。‣ 3.2 MemRefine ‣ 3 方法 ‣ MemRefine：用于长期智能体记忆的 LLM 引导压缩”) 总结了该过程，每个步骤详述如下。

##### 候选对选择。

在每次迭代中，MemRefine 选择尚未判断的最相似的条目对，表示如下： (u,v)←arg⁡max(u,v)∉𝒮⁡cos⁡(eu,ev)(u,v)\leftarrow\arg\max\_{(u,v)\notin\mathcal{S}}\cos(e\_{u},e\_{v}), 其中 eue\_{u} 表示嵌入 mum\_{u} 和 𝒮\mathcal{S} 缓存之前被判断为保留的条目对，以避免在后续迭代中重新访问它们。值得注意的是，这里的相似性仅充当“提议”机制：它显示内容最有可能重叠的对，但不能确定是否应删除任何一个条目。这种分离很重要，因为高余弦相似性同样可以表示冗余、互补性或仅仅是主题重叠，所有这些都需要不同的操作。

然后将所选对 (u,v)(u,v) 传递给 LLM 判断： d←Judge​(u,v)d\leftarrow\texttt{Judge}(u,v), 返回一个结构化决策 dd，其中包含操作 d.action∈{delete,merge,preserve}d.\mathrm{action}\in\{\textsc{delete},\textsc{merge},\textsc{preserve}\}, 一个可选的删除目标，以及（当操作是合并时）指定应保留哪些事实的合并指令。提示法官对 uu 和 vv 的事实内容进行推理，以便具有不同事实的词汇相似条目不会被折叠，并且编码相同事实的词汇不同条目被认为是冗余的（参见附录 [A.1](https://arxiv.org/html/2606.13177#A1.SS1 "A.1 提示详细信息 ‣ 附录 A A-MEM 输入表示 ‣ MemRefine: LLM 引导压缩长期智能体记忆”）以获得完整的提示）。

##### 实际意义。

值得注意的是，所提出的 MemRefine 被设计为一个离线的构建后模块，位于内存构建和检索之间：所有判断和合并调用都是在内存维护期间而不是在查询时发出的，因此压缩减少了存储的持久占用空间，而不会增加每个查询的检索或生成延迟。它还与主机内存表示无关，维护图结构框架的链接结构（在删除时修剪悬空边，在合并时继承链接的并集）（[Xu 等人，2025](https://arxiv.org/html/2606.13177#bib.bib7)），并直接对非图存储的条目及其嵌入进行操作（[Chhikara 等人， 2025](https://arxiv.org/html/2606.13177#bib.bib19));在这两种情况下，主机建设和回收管道均保持不变。

## 4 实验设置

我们的评估测试了是否可以在显式存储预算下压缩已经构建的长期记忆存储，同时保留下游效用。为了强调这一说法，我们改变了三个因素，这些因素直接控制可以删除多少存储而不降低下游实用性：主机内存框架、压缩预算和交互历史记录的长度。

##### 数据集。

我们根据长期对话记忆基准评估 MemRefine，其问题需要回忆分散在扩展的多会话对话历史中的证据。我们的主要基准是 LoCoMo（[Maharana et al., 2024](https://arxiv.org/html/2606.13177#bib.bib17)），我们使用 10 个样本，其中包含 1,986 个问题，涵盖五个类别，即单跳事实回忆、多跳推理、时间推理、开放式和反事实问题，这些问题共同探讨压缩是否保留了本地事实和分布在商店中的证据。为了在更长和更冗余的历史下进一步进行压力测试压缩，我们构建了大约 3 倍和 10 倍长对话的缩放 LoCoMo 风格数据集，这放大了主题重复性和冗余，同时也增加了在积极压缩下删除罕见但有用的事实的风险（完整的构建和质量统计数据在附录 [J](https://arxiv.org/html/2606.13177#A10“附录 J 缩放 LoCoMo 风格数据集详细信息 ‣ MemRefine）中报告： LLM 引导的长期智能体记忆压缩”））。最后，为了验证我们的发现并非特定于 LoCoMo 式评估，我们还对 LongMemEvalS（[Wu et al., 2025](https://arxiv.org/html/2606.13177#bib.bib18)）进行评估，使用 60 个问题平衡其问题类型，每种类型 10 个问题。

##### 内存框架。

为了检查构建后压缩是否可以推广到不同的内存表示形式，我们将 MemRefine 应用于以明显不同的形式存储内存的两个代表性框架。特别是，A-MEM（[Xu et al., 2025](https://arxiv.org/html/2606.13177#bib.bib7)）维护了链接的结构化笔记的图表；按照其设计，我们采用了 A-MEM 风格的事实图表示，它保留了内存内容、嵌入和链接，同时排除了辅助上下文和标签字段，从而隔离了事实图内存的压缩（附录 [A](https://arxiv.org/html/2606.13177#A1“附录 A A-MEM 输入表示 ‣ MemRefine：LLM 引导的长期智能体压缩”中提供了支持字段分析）记忆”））。相比之下，Mem0（[Chhikara et al., 2025](https://arxiv.org/html/2606.13177#bib.bib19)）通过摄取和更新管道构造条目，将原始对话转换为处理后的内存，而不是将其保留为原始对话节点。在这两种设置中，MemRefine 都会在内存构建之后和检索之前插入，从而使主机构建和检索管道保持不变。

##### 压缩预算和基线。

对于每个框架，我们在一系列存储预算下应用 MemRefine，即未压缩存储的 70%、60%、50%、40% 和 30%，这使我们能够跟踪从温和压缩到激进压缩的完整存储实用性权衡。主要的比较点是相应的未压缩基本内存，我们根据它来衡量每个预算保留了多少下游效用。为了隔离我们方法核心的 LLM 法官的贡献，我们进一步与 A-MEM 式图内存上的两个基于规则的基线进行比较，这两个基线重用相同的候选对选择循环，但用固定启发式替换事实判断：RuleSim，它根据固定的嵌入相似性阈值决定每个动作；RulePR，它通过 PageRank 式保存利用额外的图表示。这些基线直接测试表面相似性或图中心性是否足以决定哪些事实应该被删除、合并或保留。我们将这种基于规则的比较限制在图形内存中，因为两个基线都依赖于图形结构；更多详细信息请参见附录 [C](https://arxiv.org/html/2606.13177#A3“附录 C 基于规则的图形内存基线 ‣ MemRefine：用于长期智能体记忆的 LLM 引导压缩”）。

## 5 实验结果与分析

我们围绕三个问题构建我们的评估：是否可以在不牺牲下游效用的情况下压缩已经构建的内存存储，LLM指导的事实判断是否必要，或者相似性和图形结构已经足够，以及随着对话时间的延长，存储效用权衡是否仍然有利。

##### 总体结果。

表 [1](https://arxiv.org/html/2606.13177#S4.T1“表 1 ‣ 内存框架。‣ 4 实验设置 ‣ MemRefine：用于长期智能体记忆的 LLM 引导压缩”）报告了存储预算如何影响标准 LoCoMo、扩展 LoCoMo 样式设置和 LongMemEvalS 的下游性能。中心观察是 MemRefine 显着减少了内存大小，同时保留了下游效用，从而揭示了适用于所有设置的可控存储与效用权衡。在标准 LoCoMo 上，A-MEM 式图形内存和 Mem0 都保留了与中等压缩下未压缩存储相当的性能，即使删除了大量条目，F1 也基本保持不变，这表明构建的内存存储携带冗余或碎片条目，可以删除或合并这些条目，而不会丢失包含答案的内容。缩放的 LoCoMo 风格设置提供了更难的测试，因为较长的对话会带来更多的冗余，同时也增加了触及罕见但有用的事实的机会；即使在这里，MemRefine 也能在预算范围内平稳地保持效用，这表明随着交互历史的增长，它仍然有效。在 LongMemEvalS 上，A-MEM 风格的图形内存再次受益于适度的压缩，甚至在中间预算下达到最佳精度，而 Mem0 在较窄的预算范围内保留了实用性。因此，可移动的净空取决于主机表示，对于 A-MEM 样式的图形内存来说比已经整合的 Mem0 更大，但 MemRefine 将两者不变地压缩为通用后构造层而不是特定于框架的层。

##### 类别效果。

基准级别的结果表明，适度的压缩可以保持整体性能，但它们没有揭示这种效果如何在问题类型之间分布。为了检查这一点，图[3](https://arxiv.org/html/2606.13177#S4.F3“图3‣实现细节。‣4实验设置‣MemRefine：用于长期智能体记忆的LLM引导压缩”）报告了LoCoMo上相对于每个框架的未压缩基础内存的按类别F1变化（附录[F](https://arxiv.org/html/2606.13177#A6中包含完整的数值结果） “附录 F 分类 LoCoMo 结果 ‣ MemRefine：LLM 引导的长期智能体记忆压缩”））。如图[3](https://arxiv.org/html/2606.13177#S4.F3“图3‣实现细节。‣4实验设置‣MemRefine：用于长期智能体记忆的LLM引导压缩”），压缩的效果因类别而异。在 A-MEM 风格的图内存中，诸如单跳和时间问题之类的局部类别在压缩后往往会得到改善，这与构建后细化背后的直觉是一致的：当答案依赖于一个小的局部证据时，删除或合并重复的事实可以使检索的噪音更少。开放式和反事实问题的好处较少，而且对预算紧张更加敏感，因为它们的证据分布在商店的更广泛的部分。 Mem0 展示了相关但不同的类别配置文件，反映出其摄取和更新管道在应用 MemRefine 之前已将原始交互转换为经过处理的条目。总之，这些结果表明压缩的效果是由主机框架产生的问题类型和内存表示共同控制的。

##### 与基于规则的图内存的比较。

为了隔离 LLM 法官的角色，我们将 MemRefine 与基于规则的基线进行比较，这些基线保留相同的候选对选择，但用固定启发式替换事实判断，直接测试我们的中心设计选择，即相似性对于提出候选对有用，但不足以决定压缩操作。图 [4](https://arxiv.org/html/2606.13177#S4.F4“图 4 ‣ 实现细节。‣ 4 实验设置 ‣ MemRefine：用于长期智能体记忆的 LLM 引导压缩”）显示，当预算宽松时，基于规则的方法仍然具有竞争力，其中大多数决策都涉及明显的近似重复，但随着预算收紧，它们的下降幅度会更大。这是预料之中的：在积极的压缩下，困难的情况不再是近乎重复的节点，而是语义相关的记忆，其事实关系应该被解释，并且固定的相似性阈值无法将冗余的释义与补充事实分开，而图中心性并不表明记忆是否拥有未来问题所需的证据。因此，在预算紧张的情况下，MemRefine 的优势不断扩大，支持了法学硕士指导的事实行动选择的需要。

##### 压缩模型的效果。

由于 MemRefine 依赖于 LLM 判断和合并模型，因此我们接下来询问其行为是否与单个模型系列相关。图 [5](https://arxiv.org/html/2606.13177#S5.F5“图 5 ‣ 总体结果。‣ 5 个实验结果和分析 ‣ MemRefine：用于长期智能体记忆的 LLM 引导压缩”）将 GPT-5-mini 与开放的 Qwen3-8B 进行比较，同时保持下游检索和 QA 管道（完整的数值结果在附录[G](https://arxiv.org/html/2606.13177#A7“附录G压缩模型分析‣MemRefine：LLM引导的长期智能体记忆压缩”））。这两个模型在中等压缩下的表现相似，表明 MemRefine 不依赖于单一的专有判断；在预算紧张的情况下，差距会扩大，压缩需要在冗余、互补和不同的记忆之间进行更精细的区分。因此，随着存储限制变得越来越严格，更强的判断模型变得更有价值。

最后，我们问一旦历史变得更长，压缩是否仍然表现良好。图 [6](https://arxiv.org/html/2606.13177#S5.F6“图 6 ‣ 压缩模型的效果。‣ 5 实验结果和分析 ‣ MemRefine：用于长期智能体记忆的 LLM 引导压缩”）在缩放的 LoCoMo 式数据集上绘制了存储效用曲线，并且在 3 倍和 10 倍设置上，权衡保持平滑和渐进。这种平稳、可预测的行为（而不是突然的故障点）表明 MemRefine 可以作为商店不断增长的长期运行智能体的实用维护机制。

## 6 结论

在本文中，我们提出了 MemRefine，这是一种构建后内存压缩框架，旨在将已构建的长期智能体记忆存储保持在固定存储预算内，同时保留对未来交互有用的信息。通过仅使用表面候选对的相似性并将删除、合并和保留决策推迟到基于事实内容的 LLM 法官的成对细化过程，MemRefine 可以插入内存构建和检索之间，而无需修改主机内存构建管道。对 A-MEM 式图形内存、Mem0、缩放的 LoCoMo 式设置和 LongMemEvalS 的实证评估表明，适度的压缩可以保留下游效用，而更紧缩的预算会逐渐暴露存储效用权衡，随着预算收紧，与基于规则的基线之间的差距恰恰扩大。此外，我们的分析强调，安全可移动内容的数量不仅由压缩器决定，还由主机内存表示决定，A-MEM 式图形内存暴露出更多可移动冗余，而 Mem0 在摄取过程中已经过滤和合并了条目，在实用程序受到影响之前留下的空间更少。我们相信这些发现将构建后压缩确立为存储预算长期智能体记忆的实用维护层，这表明压缩和构建应该被联合考虑，而不是作为独立的阶段。

## 限制

所提出的 MemRefine 被设计为构建后模块，它将已构建的长期记忆存储压缩到目标存储预算，同时保留对下游任务有用的信息。值得注意的是，我们的评估集中在两个代表性的内存框架（链接结构化笔记的 A-MEM 式图形内存和 Mem0 摄取和更新管道）和长期会话基准上，它们一起涵盖了图形结构和处理的内存存储，但不会耗尽智能体记忆系统的空间；将构建后压缩扩展到其他内存架构并部署多智能体或工具使用设置将是未来工作的一个有价值的方向。此外，我们扩展的 LoCoMo 风格的基准测试可作为受控压力测试，用于研究随着会话长度和冗余的增长压缩如何表现，并根据扩展部署中收集的真实纵向内存日志评估 MemRefine 将是其实际适用性的令人兴奋的下一步。

## 道德考虑

拟议的 MemRefine 通过删除和合并操作编辑已经构建的长期记忆存储，这些操作会持续删除或合并过去的交互，并且在已部署的系统中可能涉及敏感的用户信息。虽然我们的实验使用公共研究基准和综合生成的缩放 LoCoMo 式数据集，而不收集或发布任何真实用户数据，但实际上，应在适当的隐私保护、访问控制和数据保留策略下应用压缩，并且我们进一步建议将其与软删除或应用编辑的审核日志等机制配对，以便维护决策保持可审查性。

## 附录 B 实施细节

##### 内存构建和检索。

除非另有说明，我们遵循原始的 A-Mem 内存构建流程，并将每个内存表示为一个图形节点及其内容和元数据。对于候选对选择，我们使用 all-MiniLM-L6-v2 嵌入每个内存条目，并计算结果嵌入的成对余弦相似度。为了回答问题，我们使用内存框架的默认检索器，通过top-k=10k=\texttt{10}检索记忆。为了控制基于 LLM 的决策的上下文长度和成本，我们将每个内存内容字段截断为前 2,000 个字符，然后再将其传递给判断和合并模型。

##### 内存大小统计。

我们通过使用ensure\_ascii=False.将存储的内存条目序列化为 JSON 来测量内存大小。对于我们的压缩变体，内存大小是通过我们的实现使用的 8 个字段来计算的。原始 A-Mem 输出还包含上下文、类别、标签和 retrieval\_count,，从而产生 12 个序列化字段。对于基于比率的压缩，每个样本的目标内存预算设置为 rr 乘以相应的无压缩内存大小，其中 r∈{0.3,0.4,0.5,0.6,0.7}r\in\{0.3,0.4,0.5,0.6,0.7\}.

##### 基于规则的压缩。

对于基于规则的删除然后合并压缩器，我们首先识别余弦相似度至少为阈值τ\tau.的冗余内存对，我们评估基于比率的预算τ∈{0.70,0.80,0.90}\tau\in\{0.70,0.80,0.90\}，并另外使用τ∈{0.75,0.85}\tau\in\{0.75,0.85\}进行绝对预算实验。在基于 PR 的设置中，PageRank 是在内存图上计算的，并且较高 PageRank 的内存优先保留在冗余集群中。除非另有说明，我们使用 PR 保护百分位 0.90.9，这可以保护前 10% 的 PageRank 节点不被选为合并锚点。如果单独删除不能满足目标内存预算，我们会回退到 A-Mem 式合并操作，其中低 PageRank 锚节点及其邻居被汇总为单个内存节点。所有压缩操作都会保留与受影响内存相关的原始时间戳。

##### LLM 判定的压缩。

对于LLM判断的压缩器，我们删除了固定的相似性阈值，而是按余弦相似性降序对候选内存对进行排序。对于每一对，判断模型决定三个操作之一：删除、合并或不执行任何操作。对于删除，法官还选择应删除哪些内存。对于合并，判断器产生合并指令，并且单独的合并模型在该指令之后生成合并的存储器。毫无疑问，该对被跳过并且不再被查询。当达到目标内存预算或没有剩余对接收压缩操作时，压缩停止。除非另有说明，判断和合并模型均为 gpt-5-mini。

##### 数据集。

对于 LoCoMo，我们评估了 10 个样本，其中包含 5 个类别的 1,986 个问题：单跳、多跳、时间问题、开放式问题和反事实问题。对于 LongMemEvalS，我们评估了六种类型的 60 个问题：单用户、单助理、单偏好、多会话、时间和知识更新问题。为了对更长的历史进行压力测试，我们构建了两个尺度（3x 和 10x）的缩放 LoCoMo 式数据集：3x 设置包括 5 个长对话样本（每个会话 80 个会话和 1,600 个用户助理回合，总共 2,720 个 QA 对），10x 设置包括 5 个样本（每个会话 270 个会话和 5,400 个回合，每个会话 9,180 个 QA 对）。总计）；完整的统计数据在附录 [J](https://arxiv.org/html/2606.13177#A10“附录 J 缩放 LoCoMo 式数据集详细信息 ‣ MemRefine：LLM 引导的长期智能体记忆压缩”）中报告。对于这两种规模，角色和事件都是使用 gpt-5-mini 生成的，而对话是使用 gpt-4o-mini 生成的。

| ---| ---| ---|
|  | {delete,s⁡(u,v)≥τdelete,merge,s⁡(u,v)<τdelete.\begin{cases}\textsc{delete},&s(u,v)\geq\tau\_{\mathrm{delete}},\\ \textsc{merge},&s(u,v)<\tau\_{\mathrm{delete}}.\end{cases} |  |

## 附录 E 仅保留基线

我们还比较了仅保留基线，这些基线保留固定百分比的现有图节点，而不执行删除合并压缩。 PageRank 保留基线根据图中心性保留排名靠前的节点，而随机保留基线保留节点的随机子集。表 [5](https://arxiv.org/html/2606.13177#A4.T5“表 5 ‣ 附录 D 基于规则的基线的阈值选择 ‣ MemRefine：用于长期智能体记忆的 LLM 引导压缩”) 显示 PageRank 保留相对于随机保留并没有提供可靠的优势。两种仅保留基线都比基于压缩的方法差得多，这表明内存压缩不仅仅是一个节点选择问题。
