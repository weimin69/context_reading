关键词：大语言模型智能体；智能体记忆；长期记忆；检索增强生成；持续适应；智能体评价

## 1 简介

扩展大型语言模型解锁了一类新的自主软件智能体——感知环境、推理目标、使用工具并在较长时间范围内采取行动的系统[[Brown et al., 2020](https://arxiv.org/html/2603.07670#bib.bib26)、[Achiam et al., 2023](https://arxiv.org/html/2603.07670#bib.bib28)、[Touvron et al., 2023](https://arxiv.org/html/2603.07670#bib.bib27)]。这些智能体与普通聊天机器人的区别不仅在于更大的模型，还在于更大的模型。这是期望他们“从经验中学习”。编码助理应该记住，特定的 API 是不稳定的，玩游戏的智能体应该回忆起它已经掌握了哪些制作配方，个人调度程序永远不应该询问用户的生日两次。所有这些都需要记忆。

### 1.1 没有它会出现什么问题

想象一个调试助手在一个大型代码库上工作一周的会话。如果没有记忆，每个星期一早上它都会重新发现目录布局，重新读取相同的自述文件，并且最糟糕的是，重试周五导致构建崩溃的确切修复。即使为同一个智能体配备一个适度的内存模块和动态变化：它到达时已经知道热点，跳过死胡同，并逐渐提炼出特定于项目的启发式方法。

这不是边际进步；而是进步。这是质的变化。记忆将无状态的法学硕士转变为“自我进化”智能体[[Zhang et al., 2024b](https://arxiv.org/html/2603.07670#bib.bib18)]，它可以（i）积累事实知识和用户偏好，（ii）根据先前的经验制定行为模式，（iii）避免重复代价高昂的错误，以及（iv）通过互动不断改进。

### 1.2 神经记忆简史

为神经网络提供外部存储的雄心可以追溯到十多年前。内存网络[[Weston et al., 2015](https://arxiv.org/html/2603.07670#bib.bib57)]及其端到端变体[[Sukhbaatar et al., 2015](https://arxiv.org/html/2603.07670#bib.bib58)]引入了对外部插槽的可微读写访问以进行问答。神经图灵机 [[Graves et al., 2014](https://arxiv.org/html/2603.07670#bib.bib59)] 和可微分神经计算机 [[Graves et al., 2016](https://arxiv.org/html/2603.07670#bib.bib60)] 进一步发展，支持通过内存矩阵进行基于内容和基于位置的寻址。记忆 Transformers [[Wu et al., 2022](https://arxiv.org/html/2603.07670#bib.bib62)] 和循环记忆 Transformers [[Bulatov et al., 2022](https://arxiv.org/html/2603.07670#bib.bib61)] 后来将显式记忆层直接集成到 Transformer 主干中。

专注于检索的并行线程。 RAG [[Lewis et al., 2020](https://arxiv.org/html/2603.07670#bib.bib1)] 将预训练的生成器与密集文档检索器结合起来，而 RETRO [[Borgeaud et al., 2022](https://arxiv.org/html/2603.07670#bib.bib2)] 表明，在推理时从*万亿*词元语料库中提取可以在参数的一小部分匹配更大的模型计数。这些系统证明了一个关键点：外部知识存储可以在生成过程中动态查询，而无需重新训练。

从检索增强的“模型”到记忆增强的“智能体”的飞跃发生得很快。 ReAct [[Yao et al., 2022](https://arxiv.org/html/2603.07670#bib.bib3)] 将推理轨迹与环境动作交织在一起，产生可解释的轨迹，兼作短视记忆。 Reflexion [[Shinn et al., 2023](https://arxiv.org/html/2603.07670#bib.bib4)] 更进一步，在任务尝试后存储口头自我批评——本质上是给智能体一份事后日志。然后是生成智能体论文 [[Park et al., 2023](https://arxiv.org/html/2603.07670#bib.bib7)]，其模拟的 25 个角色城镇表明，一个简单的观察-反思-规划循环可以产生数月的连贯社会行为。自 2023 年以来，设计空间呈爆炸式增长：受操作系统启发的分层虚拟内存[[Packer et al., 2024](https://arxiv.org/html/2603.07670#bib.bib10)]、Minecraft 中不断增长的技能库[[Wang et al., 2023a](https://arxiv.org/html/2603.07670#bib.bib8)]、作为符号内存的 SQL 数据库[[Hu et al., 2023](https://arxiv.org/html/2603.07670#bib.bib16)]，以及最近通过强化学习进行的端到端学习记忆管理[[Yu et al., 2026](https://arxiv.org/html/2603.07670#bib.bib11)]。

### 1.3 为什么要进行另一项调查？

一些广泛的智能体调查已经存在[[Xi et al., 2023](https://arxiv.org/html/2603.07670#bib.bib19)、[Wang et al., 2024a](https://arxiv.org/html/2603.07670#bib.bib20)]和Zhang et al.。 [[Zhang et al., 2024b](https://arxiv.org/html/2603.07670#bib.bib18)] 在 2024 年发表了一篇以记忆为中心的评论。然而，自那时以来，情况发生了很大变化。 2025-2026 年贡献浪潮——Agentic Memory [[Yu et al., 2026](https://arxiv.org/html/2603.07670#bib.bib11)]、MemBench [[Tan et al., 2025](https://arxiv.org/html/2603.07670#bib.bib23)]、MemoryAgentBench [[Hu et al., 2025](https://arxiv.org/html/2603.07670#bib.bib24)]，MemoryArena [[He et al., 2026](https://arxiv.org/html/2603.07670#bib.bib25)] - 引入了学习记忆控制、更丰富的评估维度以及将记忆与动作紧密结合的智能体基准。

这项调查重点关注*内存模块*并提出三个问题：

1.RQ1

   LLM智能体中的记忆应该如何分解和形式化？
2.RQ2

   存在哪些机制，它们会带来哪些权衡？
3.RQ3

   当最终测试的是下游智能体性能时，应该如何评估内存？

贡献。我们将智能体记忆形式化为 POMDP 风格的智能体循环中的写入-管理-读取循环（第 [2] 节（https://arxiv.org/html/2603.07670#S2“2 问题表述和设计目标 ‣ 自主 LLM 智能体的内存：机制、评估和新兴前沿”）），提出了一种统一不同设计的三维分类法（第[3]节（https://arxiv.org/html/2603.07670#S3“3智能体记忆的统一分类‣自主LLM智能体的内存：机制，评估和新兴前沿”）），提供深入的机制评论和具体的系统比较（第[4](https://arxiv.org/html/2603.07670#S4“4个核心内存机制‣自主LLM智能体的内存”）智能体：机制、评估和新兴前沿”））、调查基准以及实用指标堆栈（第 [5] 节（https://arxiv.org/html/2603.07670#S5“5 评估：从召回到智能体效用 ‣ 自主 LLM 智能体的记忆：机制、评估和新兴前沿”））、地图应用程序（其中内存是差异化因素） （第 [6] 节（https://arxiv.org/html/2603.07670#S6“6 内存决定或破坏智能体的地方 ‣ 自主 LLM 智能体的内存：机制、评估和新兴前沿”）），讨论工程现实和架构模式（第 [7] 节（https://arxiv.org/html/2603.07670#S7“7 工程现实 ‣ 自主 LLM 智能体的内存：机制、评估、和新兴前沿”）），相对于先前调查的位置（第 [8] 节（https://arxiv.org/html/2603.07670#S8“8 相对于先前调查的定位 ‣ 自主 LLM 智能体的记忆：机制、评估和新兴前沿”）），并绘制开放研究方向（第 [9] 节（https://arxiv.org/html/2603.07670#S9“9 开放挑战 ‣ 记忆）”自主法学硕士智能体：机制、评估和新兴前沿”））。

## 2 问题表述和设计目标

### 2.1 通过记忆看到的智能体循环

在每个离散步骤 tt 中，智能体接收输入 xtx\_{t}—a 用户消息、传感器读数或工具返回值，并且必须产生一个操作 ata\_{t}. 在这两个事件之间，它会查阅其累积的内存。我们写：

|  |  |  |  |  |
| ---| ---| ---| ---| ---|
|  | at\displaystyle a\_{t} | =πθ​(xt,ℛ⁡(Mt,xt),gt),\displaystyle=\pi\_{\theta}\!\bigl(x\_{t},\;\mathcal{R}(M\_{t},x\_{t}),\;g\_{t}\bigr), |  | (1) |
|  |  |  |  |  |
| ---| ---| ---| ---| ---|
|  | Mt+1\displaystyle M\_{t+1} | =𝒰⁡(Mt,xt,at,ot,rt),\displaystyle=\mathcal{U}\!\bigl(M\_{t},x\_{t},a\_{t},o\_{t},r\_{t}\bigr), |  | (2) |

其中πθ\pi\_{\theta}是策略（通常是提示或部分微调的LLM），ℛ\mathcal{R}从内存中读取，𝒰\mathcal{U}写入并管理内存，gtg\_{t}编码活动目标，oto\_{t}是环境反馈，以及rtr\_{t} 是任何类似奖励的信号。

有两个方面值得强调。首先，𝒰\mathcal{U}“不是”一个简单的附加操作。在设计良好的系统中，它会进行总结、删除重复、确定优先级、解决矛盾，并在适当的时候进行删除。其次，πθ\pi\_{\theta}和(ℛ,𝒰)(\mathcal{R},\mathcal{U})形成反馈循环：智能体的决策决定了要写入的内容，而写入的内容会影响未来的决策。这种递归依赖性使得内存既强大又脆弱——一次错误的写入可能会污染下游许多步骤的存储。

### 2.2 连接到 POMDP

正式来说，上面的设置是一个部分可观察的马尔可夫决策过程。记忆MtM\_{t}扮演着智能体的“信念状态”的角色：历史的内部总结，代表了世界不可观察的真实状态。经典的 POMDP 求解器通过贝叶斯过滤更新信念； LLM 智能体通过自然语言压缩、向量索引或结构化存储做类似的事情，尽管更混乱。

这个类比澄清了一个重要的观点：智能体记忆不仅仅是一个数据库查找问题。它是关于维护交互历史的“足够的统计数据”，以进行良好的操作选择，并受到硬计算和存储预算的影响。

### 2.3 五个设计目标及其张力

在我们回顾的系统中，记忆机制沿着五个轴延伸：

*•

  效用——记忆真的能改善任务结果吗？
*•

  效率 – 每单位效用的词元、延迟和存储成本是多少？
*•

  适应性——系统能否在不进行全面重新训练的情况下根据交互反馈逐步更新？
*•

  忠诚度——召回的信息是否准确且最新？陈旧的或幻觉的回忆可能比根本没有回忆更糟糕。
*•

  治理 – 系统是否尊重隐私、支持删除请求并遵守组织政策？

这些目标朝着相反的方向发展。最大化实用性会诱使您存储所有内容，这会导致存储膨胀并造成治理难题。积极的压缩提高了效率，但默默地放弃了一个罕见的事实，而三周后事实证明这一事实至关重要。任何真正的部署都必须谨慎地进行这些权衡，并且“正确的”平衡点会随着应用程序的变化而变化。医疗分诊智能体如果错过过敏记录可能会危及生命，其运作的忠诚度与效率边界与休闲食谱推荐员截然不同。理解这些张力不仅仅是学术上的——它直接影响架构选择，正如我们在后续章节中讨论的那样。

### 2.4 内存作为差异化因素：实证视角

存储器设计的实际重要性也许可以通过最近系统报告的消融结果得到最好的说明。在生成智能体实验中[[Park et al., 2023](https://arxiv.org/html/2603.07670#bib.bib7)]，移除反射组件会导致智能体行为从连贯的多日计划退化为 48 个模拟小时内重复的、与上下文无关的响应。没有技能库的 Voyager [[Wang et al., 2023a](https://arxiv.org/html/2603.07670#bib.bib8)] 在技术树里程碑速度上损失了15.3×\times——技能库*就是*性能。在 MemoryArena [[He et al., 2026](https://arxiv.org/html/2603.07670#bib.bib25)] 中，将活动内存智能体替换为仅长上下文基线，使相互依赖的多会话任务的任务完成率从 80% 以上下降到大约 45%。

这些数字强调了一个反复出现的主题：“有记忆”和“没有记忆”之间的差距往往比不同法学硕士骨干之间的差距更大。投资内存架构可以产生与模型扩展相媲美或超过的回报。

## 3 智能体记忆的统一分类

认知科学家长期以来区分了人脑中的多个记忆系统[[Atkinson and Shiffrin, 1968](https://arxiv.org/html/2603.07670#bib.bib29), [Tulving, 1972](https://arxiv.org/html/2603.07670#bib.bib30), [Baddeley, 2000](https://arxiv.org/html/2603.07670#bib.bib31), [Squire, 2004](https://arxiv.org/html/2603.07670#bib.bib32)]。智能体设计者通常无意识地反映了这种结构。我们沿着三个正交维度组织空间。

### 3.1 时间范围

工作记忆。当前上下文窗口内的任何内容都构成了智能体的工作记忆。 Baddeley 的中央执行程序加缓冲区模型 [[Baddeley, 2000](https://arxiv.org/html/2603.07670#bib.bib31)] 巧妙地映射：LLM 是执行程序，上下文窗口是缓冲区，两者共享相同的瓶颈 - 有限的容量。

情景记忆。具体经历的记录：单独的工具调用、对话轮流、环境观察。在生成智能体世界中[[Park et al., 2023](https://arxiv.org/html/2603.07670#bib.bib7)]，每个观察结果（“伊莎贝拉下午 3 点在公园看到克劳斯画画”）都会带有时间戳、重要性得分和嵌入以供以后检索。

语义记忆。抽象的、脱离情境的知识。像“用户在 1 月 5 日、1 月 12 日和 2 月 1 日更正了日期格式”这样的情景事实可以合并到语义记录“用户更喜欢 DD/MM/YYYY”。这种整合很少是自动的；大多数当前系统需要明确的提示或启发式触发器。

程序记忆。可重用的技能和可执行的计划。 Voyager 的技能库 [[Wang et al., 2023a](https://arxiv.org/html/2603.07670#bib.bib8)] 是最明显的例子：每个经过验证的 Minecraft 例程都存储为可运行的 JavaScript，由自然语言描述索引，并为新颖的任务动态组合。

在实践中，大多数智能体至少混合了其中的两种。困难的问题是“转换策略”：情景记录何时升级到语义状态，以及语义事实何时实例化回到特定任务的工作记忆中？

为了说明这种相互作用，请考虑处理退货的客户支持智能体。每个返回请求构成一个情景记录。在处理了数百个类似的请求后，智能体可能会将模式合并为语义规则：“在 7 天内收到损坏物品的客户有资格获得快速更换。”当新请求到达时，该语义规则会与当前案例的具体情节细节一起加载到工作内存中。如果智能体还存储了用于处理返回的脚本（程序记忆），则四种记忆类型形成一个完整的推理堆栈：程序表示*如何*，语义记忆表示*策略是什么*，情景记忆表示*发生了什么*，工作记忆保存实时推理上下文。

这种四层集成是我们的愿望；大多数当前系统仅很好地实现了两层，并通过粗略的启发式处理层之间的转换。整合步骤——情节变成语义知识——尤其没有得到充分的服务：它通常需要明确的开发人员规则或定期的法学硕士驱动的总结，这两者都很脆弱且难以验证。

### 3.2 代表性底物

内存的物理存储方式限制了智能体可以有效地利用它执行的操作。

上下文驻留文本——摘要、草稿本、思想链痕迹[[Wei et al., 2022](https://arxiv.org/html/2603.07670#bib.bib5)]——是最简单的基底。完全透明、零基础设施，但容量受到严格限制。

矢量索引存储将记录编码为密集嵌入，并支持近似最近邻搜索[[Karpukhin et al., 2020](https://arxiv.org/html/2603.07670#bib.bib35)、[Johnson et al., 2021](https://arxiv.org/html/2603.07670#bib.bib36)]。它们可以优雅地扩展到数百万条记录，但会失去结构化关系：您可以问“什么是最相似的？”但不是“什么导致了什么？”

结构化存储 - SQL 数据库 [[Hu et al., 2023](https://arxiv.org/html/2603.07670#bib.bib16)]、键值映射、知识图 [[Ji et al., 2022](https://arxiv.org/html/2603.07670#bib.bib37)] - 保留关系结构并支持复杂查询（“过去 7 天内涉及服务 X 的所有 API 故障”），但代价是前期架构设计。

可执行存储库——代码库、工具定义、计划模板[[Wang et al., 2023a](https://arxiv.org/html/2603.07670#bib.bib8)]——让智能体直接调用存储的技能，避开重新生成及其引入的错误。

混合商店是生产中的常态。例如，MemGPT [[Packer et al., 2024](https://arxiv.org/html/2603.07670#bib.bib10)] 在可搜索召回数据库和向量索引存档上分层了一个上下文窗口“主存储器”——每一层都有不同的访问模式和逐出规则。

### 3.3 控制策略

也许最重要且讨论最少的维度是“谁决定”存储什么、检索什么以及丢弃什么。

启发式控制硬编码规则：top-kk 检索、每 nn 轮汇总、使早于 dd 天的记录过期。可预测、易于调试，但对上下文视而不见。

提示自我控制将内存操作公开为工具调用，并让 LLM 决定何时调用它们。 MemGPT 的 core\_memory\_append 和 archival\_memory\_search 是典型示例 [[Packer et al., 2024](https://arxiv.org/html/2603.07670#bib.bib10)]。这里的质量取决于法学硕士的指令跟踪能力以及内存 API 在系统提示中的记录情况。

学习控制将内存操作视为端到端优化的策略操作。 Agentic Memory [[Yu et al., 2026](https://arxiv.org/html/2603.07670#bib.bib11)] 通过具有逐步 GRPO 的三阶段 RL 管道，将存储、检索、更新、总结和丢弃作为可调用工具进行训练。回报是巨大的——学习策略发现非显而易见的策略，例如在上下文完整之前进行先发制人的总结——但培训成本也是如此。

## 4 个核心内存机制

我们现在详细研究每个机制系列，将讨论建立在具体的系统设计及其经验权衡的基础上。

### 4.1 上下文驻留内存和压缩

为座席提供记忆的最直接方法是在提示中保留相关信息。系统消息、最近的对话轮次、草稿本笔记——法学硕士在每次通话中“看到”的所有内容都充当工作记忆，具有完美的窗口内回忆功能。

当历史超出了窗口范围时，麻烦就开始了。已经出现了几种压缩策略：（i）*滑动窗口*保留最近的 nn 个回合并丢弃其余的； (ii) *滚动摘要*，定期将较旧的历史压缩为较短的概要； (iii) *按轮流、会话和主题粒度进行操作的分层摘要； (iv) *任务条件压缩*，其中当前查询决定历史记录的哪些部分保留完整细节。自控记忆系统[[Liang et al., 2023](https://arxiv.org/html/2603.07670#bib.bib17)]将这个决定交给智能体本身，让它选择哪些片段值得逐字保留而不是积极压缩。

上下文驻留记忆是透明的且无需基础设施，但它具有众所周知的病态：*摘要漂移*。每次压缩都会默默地丢弃低频细节。经过足够多的传递后，智能体会“记住”经过清理的通用历史版本——正是这种在边缘情况下失败的记忆。将上下文窗口扩展到 100k+ 词元 [[Chen et al., 2023](https://arxiv.org/html/2603.07670#bib.bib46)] 会延迟问题，但无法消除它，并且较长的上下文会导致注意力成本呈二次方增加。

为了具体说明这一点：考虑一个每天处理 50 次用户交互的智能体。经过一周的滚动总结，原始的 350 回合历史记录已被压缩了至少三个总结周期。从第一天开始的一条罕见但关键的指令（例如，“永远不要直接调用生产数据库”）可能会在第一次压缩中幸存下来，但正是那种低频、高重要性的细节，往往会在第三次压缩时消失。然后，智能体继续调用生产数据库，产生可预测的结果。

这不是假设的故障模式；而是假设的故障模式。它反映了部署的长期运行的聊天机器人和编码助手中报告的问题。含义很明确：对于任何预计运行多个会话的智能体，应使用能够以完全保真度保存原始记录的外部存储来补充（不是替换，而是补充）上下文驻留内存。

上下文驻留记忆的一个不太明显但同样重要的限制是“注意力稀释”。即使在足够大的窗口内，LLM 的注意力机制也必须在所有词元之间分配容量。随着更多的记忆内容被注入，模型专注于任何单个片段的能力会下降——这种现象在“迷失在中间”的文献中被经验地记录下来，其中位于长上下文中心的信息比开头或结尾的信息更不可靠。这表明简单地增大窗口并不是一个完整的解决方案。智能体还必须“管理”进入窗口的内容，这让我们回到了检索和过滤机制的基本需求。

### 4.2 检索增强记忆存储

RAG [[Lewis et al., 2020](https://arxiv.org/html/2603.07670#bib.bib1)] 证明，将生成器与非参数检索索引配对可以在知识密集型任务上产生出色的结果。在智能体设置中，商店中填充的不是百科全书文章，而是“实时交互记录”：工具调用日志、环境观察、用户更正、部分计划和口头反思。

索引粒度。细粒度索引（单个工具调用或单个句子）可以提供精确的回忆，但可以将多步骤推理分割成无意义的碎片。粗粒度索引（完整会话或长段落）保留了上下文，但将信号淹没在噪音中。实用的最佳点是多粒度索引，检索器自适应地选择正确的分辨率。通过学习编码器进行的密集段落检索[[Karpukhin et al., 2020](https://arxiv.org/html/2603.07670#bib.bib35)]，通常由 FAISS 风格的近似最近邻搜索支持[[Johnson et al., 2021](https://arxiv.org/html/2603.07670#bib.bib36)]，仍然是默认实现，通常通过稀疏 BM25 和元数据过滤器（时间戳、工具类型、任务）进行增强标签）。

查询表述。许多系统都掩盖了一个微妙之处：智能体的立即输入xtx\_{t}通常是一个糟糕的检索查询。用户询问“为什么会崩溃？”需要智能体检索两个会话前的崩溃日志，而不是语义上最相似的句子。策略包括 LLM 重新制定的查询、具有结果融合的多查询扇出以及使用当前子目标作为附加检索信号。 Self-RAG [[Asai et al., 2024](https://arxiv.org/html/2603.07670#bib.bib54)] 更进一步，教导模型决定*是否*检索是必要的——一个简单的门，可以大大减少不必要的延迟。

规模。 RETRO [[Borgeaud et al., 2022](https://arxiv.org/html/2603.07670#bib.bib2)] 和对万亿词元数据存储的后续工作 [[Raad et al., 2024](https://arxiv.org/html/2603.07670#bib.bib56)] 表明检索内存可以扩展到多年的交互历史，而无需架构更改。瓶颈决定性地从存储转移到“相关性”：确保返回最“有用”（而不仅仅是最“相似”）的记录。

读写存储器。 RET-LLM [[Sun et al., 2024](https://arxiv.org/html/2603.07670#bib.bib53)] 通过让智能体在存储时编写结构化三元组，同时通过自然语言查询它们，来桥接自由格式检索和结构化存储。这是一个务实的妥协：写入时的模式，读取时的灵活性。

### 4.3 反思性和自我改进记忆

Reflexion [[Shinn et al., 2023](https://arxiv.org/html/2603.07670#bib.bib4)] 引入了一个看似简单的想法：在任务失败后，让智能体编写自然语言事后分析，然后将其添加到下一次尝试的提示中。没有梯度更新，没有奖励模型——只是一个自我批评的文本文件。结果是惊人的：HumanEval 上的通过率@1 为 91%，而没有反射的GPT-4 为 80%。

Generative 智能体 [[Park et al., 2023](https://arxiv.org/html/2603.07670#bib.bib7)] 构建了更丰富的管道。原始观察结果以情景流的形式积累。智能体会定期对相关观察结果进行聚类，并综合更高阶的*反射*，例如，“Klaus 一直在独自吃饭，似乎很孤僻。”检索通过新近度（指数衰减）、相关性（嵌入相似性）和重要性（自我评估的整数）的加权组合对记忆进行评分。这种多信号评分比纯余弦相似性有了很大的改进，并且在以后的设计中仍然具有影响力。

ExpeL [[Zhao et al., 2024](https://arxiv.org/html/2603.07670#bib.bib50)] 通过系统地对比成功和失败的轨迹、提取有区别的“经验法则”并将其存储为可重用的启发式方法，进一步推动了这一范式。内存思考[[Liu et al., 2024a](https://arxiv.org/html/2603.07670#bib.bib14)]将检索与推理分开：智能体首先回忆，然后在生成响应之前对回忆的内容执行专门的思考步骤。

反思性记忆的主要风险是“自我强化错误”。如果智能体错误地得出“API X 总是返回参数 Y 的错误”的结论，它将永远避免该调用路径，永远不会收集证据来推翻错误的信念。过度概括是同级风险：在一种情况下吸取的教训盲目地应用于另一种情况。质量门——置信度分数、与其他记忆的矛盾检查、定期过期——是必要的，但仍然不发达。

随着规模的扩大，问题变得更加严重。短命智能体的一次错误反射造成的损害有限；同样的错误反映持续存在于长期运行的生产智能体中，可能会在数周内影响数千个下游决策，这可能是灾难性的。反射内存故障模式的严重性与智能体生命周期成正比，这使得它在最需要内存的设置中特别危险。

最近的工作中探索的一种缓解策略是“反射接地”：要求智能体为其生成的每个反射引用特定的情景证据。如果“API X 不可靠”的反映必须指向三个具体的故障实例，那么智能体就不太可能生成毫无根据的概括。这并不能完全解决问题——引用的证据本身可能不具有代表性——但它提供了可供人类操作员审查的可审计线索。

### 4.4 分层内存和虚拟上下文管理

MemGPT [[Packer et al., 2024](https://arxiv.org/html/2603.07670#bib.bib10)] 借用了操作系统设计者几十年前完善的一个想法：虚拟内存。操作系统通过在 RAM 和磁盘之间透明地分页数据，为每个进程提供了巨大、连续内存的错觉。 MemGPT 对 LLM 的上下文窗口执行相同的操作：

*•

  主上下文（RAM）：保存系统提示、最近消息和当前相关记录的活动窗口。
*•

  回忆存储（磁盘）：所有过去消息的可搜索数据库。
*•

  档案存储（冷存储）：文档和长期知识的向量索引存储。

智能体通过调用内存管理“functions”—archival\_memory\_search,core\_memory\_append,等在层之间移动数据。中断机制将每个用户消息或计时器事件的控制权传递给智能体，使其在响应之前执行多个内部存储器操作。

JARVIS-1 [[Wang et al., 2024b](https://arxiv.org/html/2603.07670#bib.bib51)] 将分层原则扩展到多模式设置，为视觉观察、文本计划和可执行技能提供单独的存储。语言智能体的认知架构 [[Sumers et al., 2024](https://arxiv.org/html/2603.07670#bib.bib15)] 提出了一个通用的蓝图，其中工作存储、情景存储、语义存储和程序存储通过中央执行程序 (LLM) 进行交互，直接呼应了 Baddeley 的模型 [[Baddeley, 2000](https://arxiv.org/html/2603.07670#bib.bib31)]。

分层记忆的致命弱点是“编排”。分页错误的内容会浪费宝贵的上下文标记；归档过于激进，就会造成“记忆失明”——智能体根本不知道关键事实存在于冷存储中的某个地方。这种张力激发了下一个机制系列。

值得注意的是，分层内存中的编排失败往往是“无声的”。与产生错误消息的崩溃 API 调用不同，逐出错误记录的分页决策只会导致稍差的响应 — 没有例外，没有日志条目，没有明显的信号表明出现了问题。 Over time, these silent failures compound.诊断它们需要详细的内存操作日志和回顾性分析，这是当前很少有系统进行的工程投资，但这对于生产级部署至关重要。

### 4.5 Policy-learned memory management

启发式和提示性自我控制并未针对智能体的最终任务进行优化。 kk 最近邻检索器不知道检索到的记录是否真的有帮助；固定的摘要时间表并不关心被压缩的材料是否重要。

Agentic Memory (AgeMem) [[Yu et al., 2026](https://arxiv.org/html/2603.07670#bib.bib11)] 通过将五种内存操作（存储、检索、更新、总结、丢弃）视为智能体策略中的可调用工具，然后通过强化学习优化整个管道来解决此问题。训练分三个阶段进行：记忆演示的监督预热、带有结果奖励的任务级强化学习，以及最后为个人记忆动作提供更密集的信用分配的步骤级 GRPO。在五个长期基准测试中，AgeMem 始终优于强大的基线，并且学习的策略呈现出不明显的策略：在上下文填满之前主动总结中间结果，并有选择地丢弃在语义上与现有记录相似但不添加新信息的记录。

公开的担忧依然存在。 RL training over long horizons is expensive.习得性遗忘可能会删除对安全至关重要的信息。针对一项任务分配训练的策略可能无法转移。而且很难解释“为什么”智能体选择特定的记忆动作——可解释性落后于能力。

### 4.6 参数记忆和基于权重的适应

上述所有内容都将内存视为模型权重的外部。另一种系列通过微调或适配器模块将内存嵌入到参数“内部”。 MemLLM [[Modarressi et al., 2024](https://arxiv.org/html/2603.07670#bib.bib13)] 微调 LLM 以与显式读写内存模块交互，紧密耦合参数和非参数知识。检索和生成的联合训练[[Zhong et al., 2022](https://arxiv.org/html/2603.07670#bib.bib63)]比冻结检索器基线产生更好的内存利用率。

参数内存提供无缝集成——模型只是“知道”事物。但它很难审计（用户的生日到底存储在权重中的哪里？），很难删除（机器取消学习仍然不成熟），并且更新成本昂贵（每个新事实都需要微调）。由于这些原因，大多数部署的智能体都倾向于非参数、可检查的存储。

## 5 评估：从回忆到智能体效用

### 5.1 为什么经典检索指标不足

Precision@kk 和 nDCG 告诉您是否检索到了正确的文档。他们没有提及智能体是否正确“使用”了该文档，或者检索该文档是否值得延迟。智能体记忆评估必须联合评估“记忆质量”和“决策质量”，以及经典 IR 完全忽略的问题：陈旧、矛盾、遗忘质量和治理合规性。

### 5.2 新的基准格局

最近的四个基准将评估推向互补的方向。

LoCoMo [[Maharana et al., 2024](https://arxiv.org/html/2603.07670#bib.bib22)] 测试非常长期的对话记忆：最多 35 个会话、300 多个回合以及每个对话 9k-16k 词元。三个评估任务——事实问答、事件总结和对话生成——探讨不同的记忆需求。总体结果是：即使是 RAG 增强型法学硕士也远远落后于人类，尤其是在时间和因果动态方面。

MemBench [[Tan et al., 2025](https://arxiv.org/html/2603.07670#bib.bib23)] 将“事实”记忆与“反思”记忆区分开来，并在“参与”和“观察”模式下分别进行测试。指标涵盖三个维度：有效性（准确性）、效率（内存操作数量）和容量（随着内存存储的增长而导致性能下降）。

MemoryAgentBench [[Hu et al., 2025](https://arxiv.org/html/2603.07670#bib.bib24)] 以认知科学为基础进行评估，探讨四种能力：准确检索、测试时学习、长期理解和选择性遗忘。长上下文数据集被重新格式化为增量多轮交互，以模拟实际积累。当前的系统还没有掌握所有四种能力；大多数人在选择性遗忘方面明显失败。

MemoryArena [[He et al., 2026](https://arxiv.org/html/2603.07670#bib.bib25)] 将记忆评估嵌入到完整的智能体任务中——网络导航、偏好约束规划、渐进式信息搜索和顺序形式推理——其中后面的子任务取决于智能体从早期子任务中学到的东西。最引人注目的发现：在 LoCoMo 上得分近乎完美的模型在 MemoryArena 中骤然下降至 40-60%，暴露出被动回忆与主动、决策相关的记忆使用之间的巨大差距。

### 5.4 实用的度量堆栈

部署需要比任何单一基准提供的更多细微差别。我们提出一个四层评估堆栈：

第一层——任务有效性：成功率、事实正确性、计划完成率。

第 2 层——内存质量：检索记录的精确度/召回率、矛盾率、陈旧性分布、任务相关事实的覆盖范围。

第 3 层 - 效率：每次内存操作的延迟、内存内容消耗的提示词元、每步的检索调用、存储随时间的增长。

第 4 层——治理：隐私泄露率、删除合规性、访问范围违规。

消融研究应该隔离写入策略、检索策略和压缩模块，将增益归因于特定组件而不是整个管道。

### 5.5 基准测试中的跨领域经验教训

汇总这四项评估的结果，可以发现一些突出的模式。

长上下文不是记忆。尽管上下文窗口扩展到 200k 个标记[[Chen et al., 2023](https://arxiv.org/html/2603.07670#bib.bib46)]，但在需要选择性检索和主动管理的任务上，长上下文模型始终表现不佳专门构建的记忆系统。 MemoryArena 让这一点变得最明显：被动回忆王牌是糟糕的记忆剂。

RAG 有所帮助，但与人类的差距很大。基于 RAG 的智能体全面击败了纯长上下文基线，但主要瓶颈不再是存储，而是“检索质量”。特工经常会公开看似合理但陈旧或偏离主题的记录[[Maharana et al., 2024](https://arxiv.org/html/2603.07670#bib.bib22)]。

没有人能够很好地评价遗忘。只有 MemoryAgentBench 显式测试选择性遗忘。然而，在任何长期运行的部署中，无法丢弃过时的信息会逐渐损害检索精度。

跨会话一致性尚未得到充分探索。大多数基准测试都会衡量会话内的性能。 MemoryArena 的多会话设计表明，在相隔数小时或数天的会话中保持一致的知识和行为是一个独特的挑战，而且基本上尚未解决。

参数与非参数之间的差距是真实存在的。具有参数存储器（微调权重）和非参数存储器（外部存储）的系统显示不同的故障情况。参数化记忆擅长无缝知识整合，但不擅长有针对性的删除和审计。非参数内存支持检查和治理，但可能会让人感觉“被束缚”——智能体有时会忽略检索到的记录或不一致地使用它们。这两种方法之间的最佳平衡以及如何有效地将它们结合起来仍然是一个悬而未决的实证问题。

评估必须包括成本。内存系统的准确度提高了 5%，但延迟和存储成本却增加了三倍，这在实践中可能并不是一种改进。目前的基准都没有系统地报告效率指标和有效性，因此很难评估报告的收益是“免费”还是以巨大的运营费用获得。未来的评估应该要求至少报告词元消耗和延迟开销以及准确度数字。

## 6 记忆决定特工的成败

记忆并不是一律重要的。一次性翻译工具几乎不需要它；一个为期一个月的项目合作者如果没有它就无法运作。下面我们将研究内存是差异化因素的领域。

### 6.1 私人助理和对话智能体

私人助理忘记你的饮食限制或每次会话都重新询问你的时区，这充其量只是烦人的。 MemoryBank [[Zhong et al., 2024](https://arxiv.org/html/2603.07670#bib.bib12)] 通过艾宾浩斯遗忘曲线模拟记忆衰退[[Ebbinghaus, 1885](https://arxiv.org/html/2603.07670#bib.bib34)]：频繁访问、高度重要的记忆会得到强化，而被忽视的记忆会逐渐消失。 MemGPT [[Packer et al., 2024](https://arxiv.org/html/2603.07670#bib.bib10)] 演示了具有不断发展的用户模型的多会话聊天。该领域的核心张力是“个性化但不越界”——智能体必须记住足够多的信息才能真正提供帮助，而不会泄露用户认为私密或遗忘的信息。

### 6.2 软件工程智能体

编码智能体协助跨可能包含数百万行的代码库进行生成、调试、审查和项目管理[[Qian et al., 2024](https://arxiv.org/html/2603.07670#bib.bib40)、[Hong et al., 2024](https://arxiv.org/html/2603.07670#bib.bib39)]。内存要求很高：保留架构决策、跟踪错误报告历史、记住代码风格首选项以及维护经过验证的解决方案库。 ChatDev [[Qian et al., 2024](https://arxiv.org/html/2603.07670#bib.bib40)] 为角色扮演智能体（CEO、CTO、程序员、测试人员）配备共享内存，以保持项目在各个开发阶段的一致性。 MetaGPT [[Hong et al., 2024](https://arxiv.org/html/2603.07670#bib.bib39)] 将这种共享内存构建为标准化文档（PRD、设计规范、代码模块），并且持续存在并不断发展。

这里的独特挑战是“结构规模”：内存系统必须索引和检索可能跨越数千个文件而不仅仅是对话的代码库的相关部分。

### 6.3 开放世界游戏智能体

《我的世界》和类似的沙盒之所以成为流行的测试平台，正是因为它们需要长期规划和组合技能重用。 Voyager [[Wang et al., 2023a](https://arxiv.org/html/2603.07670#bib.bib8)] 表明，不断增长的技能库可以实现终身学习：与之前的智能体相比，3.3×\times 更多独特的项目和 15.3×\times 更快的里程碑进展。 JARVIS-1 [[Wang et al., 2024b](https://arxiv.org/html/2603.07670#bib.bib51)] 通过涵盖视觉观察和文本计划的多模态记忆扩展了这一点。 《Minecraft 中的幽灵》[[Zhu et al., 2023](https://arxiv.org/html/2603.07670#bib.bib43)] 使用基于文本的知识和记忆来构建具有普遍能力的开放世界智能体。

关键的挑战是“组合技能的重用”：智能体不仅必须回忆个人技能，还必须创造性地将它们链接起来以解决新问题。

### 6.4 科学推理和发现

科学智能体必须跟踪假设、记录实验结果、消化文献并随着证据的积累修正信念。内存在这里充当假设分类账和证据累积器。独特的挑战是“不确定性感知记忆”：智能体不仅必须维护事实，还必须维护置信水平，并在新数据到达时正确更新它们——大多数当前的记忆系统对此处理不佳或根本不处理。

### 6.5 多智能体协作

当多个智能体一起工作时，记忆就成为一种协调机制。 AutoGen [[Wu et al., 2023](https://arxiv.org/html/2603.07670#bib.bib44)] 让智能体可以通过共享上下文构建彼此的贡献。 CAMEL [[Li et al., 2024](https://arxiv.org/html/2603.07670#bib.bib45)] 探索必须记住先前协议和协作历史的角色感知沟通智能体。 ProAgent [[Zhang et al., 2024a](https://arxiv.org/html/2603.07670#bib.bib52)] 培养积极主动的队友，根据过去互动的记忆来预测需求。

两个挑战占主导地位：*共享内存与私有内存边界*——什么应该对谁可见？——以及*并发写入下的一致性*——当两个智能体同时更新共享内存时会发生什么？当前的多智能体框架以两种方式之一处理共享内存：要么共享所有内存（简单但泄漏私有信息），要么每个智能体维护自己的存储而不进行跨智能体访问（隔离但阻止知识传输）。这两个极端都不能令人满意。有原则的中间立场将在共享内存基底上定义基于角色的访问控制，允许项目经理智能体查看来自开发人员智能体的高级摘要，而无需访问原始代码差异。适用于自然语言记录的数据库式访问控制列表是一种自然但未经探索的解决方案。

### 6.6 工具使用和API编排

使用工具的智能体[[Schick et al., 2024](https://arxiv.org/html/2603.07670#bib.bib42)]与 API、数据库和 Web 服务交互。内存必须跟踪存在哪些工具、如何调用它们、上次工作的参数以及哪些调用序列已被验证。 AgentBench [[Liu et al., 2023](https://arxiv.org/html/2603.07670#bib.bib41)] 在八个环境中评估智能体；失去命令历史记录的智能体在多步骤任务中表现出急剧的性能下降。 DERA [[Nair et al., 2023](https://arxiv.org/html/2603.07670#bib.bib55)] 使用对话轮转记忆来迭代地完善工具使用策略。

此设置特有的实际危险是“架构漂移”：当 API 更新其接口时，存储的使用模式将变得无效。对存储的工具使用记录的版本跟踪和模式验证至关重要，但很少实施。在快速发展的 API 生态系统中，不处理模式漂移的工具使用内存系统将积累越来越多的无效记录，从而逐渐降低智能体重用过去经验的能力。

这里更广泛的一点是，工具使用记忆不仅仅是存储“有用的东西”；它是关于维护一个动态的、版本化的工具功能目录，该目录会随着外部世界的变化而优雅地降级。这与依赖管理的软件工程概念相关：正如构建系统必须跟踪库版本一样，使用工具的智能体必须跟踪其内存存储中的 API 版本。

### 6.7 跨域内存传输

一个新兴方向是“跨”域传输内存，例如，将在 Python 中学到的调试启发式方法重用于 Java，或者将一个用户的时间管理策略应用于另一个用户。思想之树 [[Yao et al., 2024](https://arxiv.org/html/2603.07670#bib.bib6)] 提供了一个有意识地解决问题的框架，可以从跨域程序记忆中受益。悬而未决的问题是如何识别哪些记忆是概括性的，哪些是无可救药的特定情境记忆。

### 6.8 摘要：不同内存类型最重要的地方

应用调查揭示了一个清晰的模式：不同的领域强调不同的内存类型。个人助理最依赖于语义记忆（用户偏好和配置文件）。软件工程智能体严重依赖程序内存（经过验证的代码模式和架构决策）。游戏智能体需要情景记忆和程序记忆的紧密整合（发生了什么++如何处理）。科学智能体需要具有明确的不确定性跟踪的语义记忆。多智能体系统添加了一个协调层，目前单智能体记忆设计无法很好地处理该层。

现有的系统还没有同时对所有这些配置文件提供强大的支持，这表明智能体记忆的下一个飞跃可能来自更加模块化、可插拔的架构，其中内存组件可以根据部署进行组合和配置，而不是融入整体设计。

## 7 工程现实

### 7.1 写入路径

逐字存储每个交互是很诱人的，而且几乎总是错误的。
噪音——闲聊、多余的确认、重复的问候——会降低检索精度。
精心设计的写入路径包括：
*过滤*以拒绝低信号记录，
*规范化*标准化日期、名称和数量，
*重复数据删除*合并重叠条目，
*优先评分*按任务相关性和新颖性对记录进行排名，
和*元数据标记*（时间戳、来源、任务标签、置信度）以支持下游结构化查询。

最佳过滤阈值是特定于应用程序的。医疗智能体不能承受假阴性（遗漏药物过敏提及）；一个休闲的聊天助手可以容忍它们。在这两个极端之间存在着一个范围：企业客户支持机器人通常优先考虑对合同承诺的高召回率，但接受对随意偏好的较低召回率，而财务咨询智能体要求对监管披露进行近乎完美的召回，但可以忘记非正式的闲聊。写入路径设计应通过风险分析来确定，该风险分析将内存故障模式映射到目标域中的下游后果。

### 7.2 读取路径

并非每个步骤都需要检索，也不是每个检索都需要完整的管道。实用的读取路径优化包括：两阶段检索（快速 BM25 或元数据过滤器→\rightarrow较慢的跨编码器重排序）、检索或不检索门控[[Asai et al., 2024](https://arxiv.org/html/2603.07670#bib.bib54)]、在内存和当前任务之间动态分配上下文空间的词元预算，以及用于高频记录（如用户偏好）的缓存层。

### 7.3 陈旧、矛盾和漂移

如果私人助理按照旧地址向用户的前伴侣发送生日贺卡，不仅没有帮助，而且有害。长期存在的内存存储会积累陈旧的记录，如果没有明确的机制，智能体就无法区分 2024 年的地址和 2022 年的地址。

强大的系统需要*临时版本控制*（首选最新记录）、*源归因*（用户语句>>智能体推理）、*矛盾检测*（标记冲突以解决问题）和*定期合并*（合并重复项并淘汰陈旧条目的计划扫描）。

### 7.4 延迟和成本

用户期望简单查询的亚秒级响应。检索管道很容易就会增加 200–500 毫秒。常见的缓解措施：异步写入（将存储推迟到响应之后）、渐进检索（在检索并行运行时开始生成）和动态路由（跳过直接请求的检索，仅在模糊性较高时才使用完整管道）。

徐等人。 [[Xu et al., 2024](https://arxiv.org/html/2603.07670#bib.bib47)]表明，将一些高度相关的段落检索到中等长度的上下文中通常会击败纯长上下文和纯检索方法——这是调整延迟质量权衡的有用指南。

### 7.5 隐私、合规性和删除

智能体记忆可以保存敏感数据：健康详细信息、财务记录、私人对话。部署必须提供静态和传输中的加密、每个用户的访问范围、自动 PII 编辑、可配置的保留策略以及从每个层删除数据的可审核删除（包括向量索引条目和备份快照）。

当记忆泄漏到微调权重中时，外部删除是不够的。机器取消学习[[Bourtoule et al., 2021](https://arxiv.org/html/2603.07670#bib.bib48)、[Liu et al., 2024b](https://arxiv.org/html/2603.07670#bib.bib49)]是唯一的路径，而且距离生产就绪还很远。智能体记忆治理和机器遗忘的交叉点是一个紧迫的开放问题。

### 7.6 三种架构模式

在实践中，智能体记忆系统分为三种重复模式：

模式 A：整体上下文。所有的记忆都存在于提示中。零基础设施、完全透明，但容量有限且容易出现汇总漂移。适用于短期智能体或快速原型制作。

模式B：上下文+检索存储。上下文窗口中的工作记忆；外部向量或结构化存储中的长期记录。检索管道每一步都会注入相关记录。这是当今大多数生产智能体背后的主力模式：编码助理、客户服务机器人、企业副驾驶。工程负担是可控的；主要挑战是检索质量。

模式 C：具有学习控制的分层记忆。多层——上下文、结构化数据库、矢量存储、冷归档——由学习或提示的控制器管理。 MemGPT [[Packer et al., 2024](https://arxiv.org/html/2603.07670#bib.bib10)] 和 AgeMem [[Yu et al., 2026](https://arxiv.org/html/2603.07670#bib.bib11)] 就是范例。这种模式提供了最大的空间，但需要最复杂的工程和培训。

我们的建议：从模式 B 开始，彻底检测它，只有当经验数据表明学习控制能有效改善您的目标工作量时，才转向模式 C。

### 7.7 可观察性和调试

众所周知，内存系统很难调试。当智能体给出错误答案时，问题出在检索（出现错误记录）、写入路径（从未存储相关信息）、压缩（摘要过程中丢失细节），还是法学硕士对正确检索内容的推理中？

生产部署受益于全面的内存操作日志记录：每次写入、读取、更新和删除都应记录时间戳、触发上下文以及涉及的记录。重放工具允许开发人员使用修改后的内存内容重新运行失败的交互，这对于根本原因分析非常有价值。一些团队发现，简单的“内存差异”（显示两个对话轮之间内存存储中的变化）比传统的日志分析提供了更多的诊断价值。

研究论文中很少讨论这种可观察性基础设施，但它的缺乏是令人印象深刻的演示阶段内存系统无法过渡到可靠的生产部署的主要原因之一。

除了调试之外，内存可观察性还支持*持续改进*。通过分析内存操作中的模式（最常检索哪些类型的记录、哪些已写入但从不读取、哪些检索查询始终返回空结果），团队可以识别瓶颈并随着时间的推移校准其内存系统。这种反馈循环在数据库工程（查询性能监控、索引优化）中是标准的，但在智能体记忆实践中几乎完全不存在。借用这些技术，即使是简化形式，也将显着提高已部署的内存增强智能体的可靠性。

一个相关的问题是*记忆行为的回归测试*。当存储系统更新时（例如，为向量存储部署新的嵌入模型），对检索质量的影响是不可预测的，而且可能是微妙的。如果没有一套回归测试来验证代表性场景中的预期内存行为，内存子系统的更改就会成为未跟踪风险的来源。构建这样的测试套件需要“应该为哪些查询检索哪些内存”的真实注释，这是一项可以在系统稳定性方面带来回报的投资。

## 8 相对于之前调查的定位

习等人。 [[Xi 等人，2023](https://arxiv.org/html/2603.07670#bib.bib19)] 和 Wang 等人。 [[Wang et al., 2024a](https://arxiv.org/html/2603.07670#bib.bib20)] 提供了广泛的智能体调查，其中记忆是众多模块之一。张等人。 [[Zhang et al., 2024b](https://arxiv.org/html/2603.07670#bib.bib18)] 特别关注内存并围绕写入-管理-读取操作组织审查；我们的工作更新了 2025-2026 年系统（AgeMem、MemBench、MemoryAgentBench、MemoryArena）的覆盖范围，添加了基于 POMDP 的公式，并将讨论扩展到应用程序、工程模式和治理。

高等人。 [[Gao et al., 2024](https://arxiv.org/html/2603.07670#bib.bib21)]全面调查了RAG，但其范围是检索-生成管道，而不是特定于智能体的内存需求。苏默斯等人。 [[Sumers et al., 2024](https://arxiv.org/html/2603.07670#bib.bib15)]提出了语言智能体的认知架构蓝图；我们的分类法是互补的，共享认知科学术语，但将分析扩展到代表性基质和控制政策。

经常提出的一个问题是，是否可以扩展上下文窗口（从早期 GPT 模型中的 4k 到今天的 200k 以上）[[Chen et al., 2023](https://arxiv.org/html/2603.07670#bib.bib46)]—使外部存储器变得过时。证据表明不。较长的上下文可以扩大工作记忆，但不能提供持久的跨会话 存储、结构化知识组织、从几个月的历史记录中选择性检索或删除和访问控制等治理机制。此外，推理成本与上下文长度呈二次方关系，Xu 等人。 [[Xu et al., 2024](https://arxiv.org/html/2603.07670#bib.bib47)] 经验表明 谦虚的 在许多任务中，通过有针对性的检索增强上下文的效果优于暴力长上下文。

## 9 项公开挑战

### 9.1 原则性整合

当前的系统在囤积（储存所有东西，淹没在噪音中）和失忆（积极压缩，丢失罕见但重要的事实）之间摇摆。神经科学提供了一个有启发性的模型：在睡眠期间，海马体会重播最近的经历，加强重要的痕迹并修剪其余的[[Squire，2004](https://arxiv.org/html/2603.07670#bib.bib32)]。类似的“离线整合”流程（在空闲期间安排）可以提供原则上的平衡。开放性问题：如何在没有前瞻性的情况下估计内存重要性，如何检测何时需要整合，以及如何保证安全关键记录在整个过程中幸存下来。

一种值得探索的具体方法是“双缓冲区整合”，即新形成的记忆在试用期内驻留在“热”缓冲区中，只有在通过质量检查（重新验证、重复数据删除和重要性评分）后才会晋升为长期存储。这反映了在生物记忆中观察到的海马到新皮质的转移[[Squire, 2004](https://arxiv.org/html/2603.07670#bib.bib32)]，其中新记忆最初依赖于海马，并通过反复重新激活逐渐变得独立。在智能体系统中实现此功能需要定义试用期、升级标准以及升级发生前热缓冲区溢出时的回退行为。

### 9.2 因果检索

语义相似性回答“这看起来像什么？”但不是“是什么造成了这个？”当智能体调试系统故障时，相关内存可能在时间上较远且在语义上与当前错误消息不同，但因果上位于上游。混合语义相似性、时间排序、因果图遍历和反事实相关性的混合检索器在很大程度上仍未被探索。构建它们需要将因果发现技术与记忆索引相结合——技术上具有挑战性，但对于复杂的推理任务来说可能具有变革性。

具体的起点是使用轻量级因果元数据层来增强标准向量索引。当存储记忆记录时，智能体可以用估计的“因果父辈”（促成该记录的早期记录或事件）对其进行注释。在检索时，系统将与标准相似性搜索一起遍历这些因果链接，显示语义上遥远但因果相关的记录。这样的系统不需要执行完整的因果推理；即使是法学硕士在写入时生成的近似因果注释，也可以极大地改善根本原因分析、反事实规划和多步骤调试等推理繁重任务的检索。

### 9.3 值得信赖的反思

自我反省是一种强大的适应机制，但也可能会加深错误。如果智能体错误地得出“AA 方法总是失败”的结论，它就永远不会再次测试 AA 方法——这是一种典型的确认偏差。未来的系统需要外部验证（如果可用的话，根据真实情况检查反射）、不确定性量化（在没有确认证据的情况下随着时间的推移降低置信度）、对抗性探测（定期用反例挑战存储的信念）和过期策略（在设定的时间段后淘汰未经验证的反射）。

### 9.4 学会忘记

遗忘不是错误，而是错误。它是一项对于稳健性、隐私性和效率至关重要的功能。然而，当前的系统处理方式很粗糙：基于时间的硬性过期、存储限制驱逐，或者根本不处理。研究问题是学习“选择性”遗忘策略，在安全和合规性约束下最大化长期效用。当记忆通过上下文学习或微调影响模型行为时，与机器取消学习的联系[[Bourtoule et al., 2021](https://arxiv.org/html/2603.07670#bib.bib48)、[Liu et al., 2024b](https://arxiv.org/html/2603.07670#bib.bib49)]至关重要。

### 9.5 多模式和具身记忆

随着智能体进入机器人和混合现实，记忆必须融合文本、视觉、音频、本体感觉和工具状态。 JARVIS-1 [[Wang et al., 2024b](https://arxiv.org/html/2603.07670#bib.bib51)] 提供了 Minecraft 中的早期示例，但现实世界的具体设置增加了空间记忆、实时延迟限制以及跨模式检索的棘手问题 - 通过文本查询找到视觉记忆，反之亦然。

### 9.6 多智能体记忆治理

多智能体系统提出了单智能体记忆永远不会遇到的问题：共享存储的访问控制、并发写入的共识协议以及不同专业智能体之间的知识传输机制。当前的方法依赖于共享对话日志或文档存储；更复杂的设计——具有合并语义的分布式内存、具有每个智能体缓存的分层共享内存——仍然处于开放状态。

### 9.7 迈向内存高效架构

内存增强智能体非常昂贵：上下文窗口大、每步多次检索调用、不断增长的存储。稀疏检索（每步激活一小部分存储）、压缩会话向量、循环内存转换器等内存原生架构 [[Bulatov et al., 2022](https://arxiv.org/html/2603.07670#bib.bib61)] 以及通过适配器进行的免检索注入 [[Modarressi et al., 2024](https://arxiv.org/html/2603.07670#bib.bib13)] 都指向更便宜的替代方案，尽管没有尚未展现出强劲的智能体级表现。

### 9.8 更深入的神经科学整合

当前的智能体记忆借用了认知科学的标签；更深入的参与可以产生更好的机制。传播激活[[Anderson, 1983](https://arxiv.org/html/2603.07670#bib.bib33)]——访问一个记忆会引发相关记忆——可以改善直接相似性之外的检索。记忆再巩固理论——检索会使记忆不稳定并容易修改——可以为更新机制提供信息。艾宾浩斯曲线 [[Ebbinghaus, 1885](https://arxiv.org/html/2603.07670#bib.bib34)] 已在 MemoryBank [[Zhong et al., 2024](https://arxiv.org/html/2603.07670#bib.bib12)] 中使用，可以通过间隔重复进行扩展，以优化强化时间。

### 9.9 内存管理基础模型

长期愿景：*记忆控制的基础模型*，通过不同的智能体任务进行训练，以执行具有一般能力的写入、检索、总结、忘记和巩固操作，就像指令调整的法学硕士[[Ouyang et al., 2022](https://arxiv.org/html/2603.07670#bib.bib38)]提供一般语言能力。 AgeMem [[Yu et al., 2026](https://arxiv.org/html/2603.07670#bib.bib11)] 通过学习内存管理作为策略迈出了第一步，但真正与任务无关的内存控制器的愿景仍未实现。

这样的基础模型需要处理各种分布的内存挑战：短期会话跟踪、长期用户分析、高频工具使用日志记录、罕见但安全关键的信息保留以及存储预算耗尽时的优雅降级。训练数据要求令人望而生畏——该模型需要接触数十个领域的数千个智能体轨迹，并带有内存操作质量的真实标签。综合生成这些训练数据，也许可以通过让高级法学硕士回顾性地注释历史痕迹中的哪些内存操作是有用的或有害的，可以引导这个过程。

### 9.10 标准化评价

该领域仍然缺乏社区标准的评估工具。每个基准测试都使用自己的数据集、指标和协议，使得跨论文比较不可靠。 GLUE 式的智能体记忆共享排行榜（跨越会话、智能体和多会话轨道，具有来自我们四层堆栈的标准化指标）将大大加快进度并减少重复工作。

## 10 结论

对于基于 LLM 的智能体来说，内存已经从外围附加组件转变为核心工程和研究挑战。该领域已经快速连续经历了三代：即时级压缩、检索增强的外部存储和端到端学习记忆策略。评估也随之发展——从静态回忆测试到暴露记住事实和实际使用事实之间差距的多会话智能体基准。

这项调查提供了基于 POMDP 的形式化、三轴分类法、对五个机制系列的深入研究、结构化基准比较、应用程序级分析和实用的工程手册。但最困难的问题仍然存在：如何在不发生灾难性损失的情况下进行整合，如何通过原因而不是相似性进行检索，如何在不根深蒂固的错误的情况下进行反思，以及如何安全地忘记。解决这些问题将决定下一代智能体是否仅仅是令人印象深刻或真正可靠。

如果说这项调查有一个结论的话，那就是内存值得与法学硕士本身同等水平的工程投资。模型选择需要经过数月的仔细基准测试；内存架构经常需要一个下午的时间。这里审查的证据表明，翻转这一优先事项——将内存视为值得专门设计、测试和优化的一流系统组件——可能是当今智能体构建者可用的单一最高杠杆干预措施。
