## 来源摘要/页面简介

摘要：基于大型语言模型（LLM）的网络智能体擅长知识密集型任务，但面临着广泛探索的需要和有限上下文窗口的约束之间的根本冲突。当前的解决方案通常依赖于架构修改，例如内部存储器词元，这破坏了与预先存在的智能体的兼容性，并且需要昂贵的端到端再训练。为了克服这些限制，我们引入了 ReSum，这是一种轻量级、即插即用的范例，它通过定期调用外部工具将交互历史压缩为紧凑的摘要来实现无限制的探索。尽管这种范式无需训练即可发挥作用，但标准智能体本质上并不符合这种压缩上下文的推理。为了弥补这一差距，我们提出了 ReSum-GRPO，它通过优势广播来适应组相对策略优化（GRPO），以跨分段轨迹传播最终奖励，从而实现长期信用分配。大量实验表明，在免训练环境中，ReSum 比 ReAct 提高了 4.5%，而 ReSum-GRPO 又提高了 8.2%。值得注意的是，仅用 1K 训练样本，ReSum 增强型 30B 智能体就实现了与领先开源模型竞争的性能，显示了 ReSum 的有效性。

###### 摘要

基于大型语言模型（LLM）的网络智能体擅长于知识密集型任务，但面临着广泛探索的需要和有限上下文窗口的约束之间的根本冲突。当前的解决方案通常依赖于架构修改，例如内部存储器词元，这破坏了与预先存在的智能体的兼容性，并且需要昂贵的端到端再训练。为了克服这些限制，我们引入了 ReSum，这是一种轻量级、即插即用的范例，它通过定期调用外部工具将交互历史压缩为紧凑的摘要来实现无限制的探索。尽管这种范式无需训练即可发挥作用，但标准智能体本质上并不符合这种压缩上下文的推理。为了弥补这一差距，我们提出了 ReSum-GRPO，它通过优势广播来适应组相对策略优化（GRPO），以跨分段轨迹传播最终奖励，从而实现长期信用分配。大量实验表明，在免训练环境中，ReSum 比 ReAct 提高了 4.5%，而 ReSum-GRPO 又提高了 8.2%。值得注意的是，仅用 1K 训练样本，ReSum 增强型 30B 智能体就实现了与领先开源模型竞争的性能，显示了 ReSum 的有效性。

## 1 简介

![参考说明](https://arxiv.org/html/2509.13313v3/images/motivation.jpg)

图 1：ReAct 和 ReSum 范例之间的比较。在多轮探索完成之前，在 ReAct 中附加每个想法、行动和观察都会耗尽上下文预算。相比之下，ReSum 定期调用摘要工具来压缩历史记录并从压缩的摘要中恢复推理，从而实现无限探索。

基于大语言模型（LLM）的智能体在复杂的知识密集型任务上表现出了强大的性能（[Yao et al., 2023](https://arxiv.org/html/2509.13313#bib.bib39); [Wang et al., 2024](https://arxiv.org/html/2509.13313#bib.bib30); [Jin et al., 2025](https://arxiv.org/html/2509.13313#bib.bib8); [Xi等人，2025](https://arxiv.org/html/2509.13313#bib.bib36)；[Gao 等人，2025](https://arxiv.org/html/2509.13313#bib.bib4))。其中，网络智能体尤其重要：它们主动搜索和浏览开放网络，从不同来源提取和依据事实，并综合针对特定用户且最新的答案（[Wu et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib33)；[Li et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib11)）。

然而，回答复杂的查询并非易事。考虑这个例子：*一位画家的父亲死于心脏病，他和妻子有一个姐姐和五个孩子。后来，他的婚姻破裂了，他又谈过三段感情。以这个人为原型的文学作品叫什么名字？* 这个查询体现了网络搜索的挑战：它涉及多个实体、相互交织的关系以及具有高度不确定性的碎片信息。此类任务无法通过几次简单的搜索调用来解决；相反，他们需要延长有针对性的查询、浏览和交叉验证的周期，以逐步组装完整的证据链（[Gao et al., 2025](https://arxiv.org/html/2509.13313#bib.bib4)）。

这种长期探索的需要面临着一个根本障碍：环境限制。大多数法学硕士的上下文窗口有限（[Yang et al., 2024](https://arxiv.org/html/2509.13313#bib.bib38); [Jiang et al., 2023](https://arxiv.org/html/2509.13313#bib.bib7))，以及流行的ReAct范式([Yao et al., 2023](https://arxiv.org/html/2509.13313#bib.bib39))，它会附加每个观察结果并思考历史，很快就耗尽了这个预算（图[1](https://arxiv.org/html/2509.13313#S1.F1“图1‣1简介‣ReSum：通过上下文摘要解锁长程搜索智能”））。当前的解决方案，例如 MEM1（[Zhou et al., 2025b](https://arxiv.org/html/2509.13313#bib.bib44)）和 MemAgent（[Yu et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib40)），通常依赖于架构修改，例如生成内部内存词元。虽然有效，但这些方法破坏了与现有智能体的兼容性，并且需要端到端的再训练。

为了克服这些限制，我们引入了 ReSum，这是一种轻量级范例，可以通过上下文摘要进行无限制的探索。核心见解是“定期”调用外部工具将交互历史浓缩为紧凑的摘要。通过从这些压缩状态恢复探索，智能体可以保持对先前发现的认识，同时释放上下文空间。与之前的方法不同，ReSum 代表了一种范例性的增强，而不是架构上的改变，提供了一种即插即用的解决方案，可以通过最少的修改无缝地为现成的智能体提供支持。

有效地实现 ReSum 需要一个强大的汇总工具。一般的法学硕士常常难以区分关键的搜索证据和嘈杂、冗长的历史。因此，我们通过对来自强大开源模型的高质量⟨Conversation,Summary⟩\langle\texttt{Conversation},\texttt{Summary}\rangle对进行微调Qwen3-30B-A3B-Thinking（[团队，2025](https://arxiv.org/html/2509.13313#bib.bib28)）来开发ReSumTool-30B（[Guo et al., 2025](https://arxiv.org/html/2509.13313#bib.bib6)； [OpenAI，2025a](https://arxiv.org/html/2509.13313#bib.bib18))。 ReSumTool-30B 基于严格的数据构建流程，经过专门训练，可以提取关键线索、识别信息差距并突出下一步方向，在摘要质量方面优于 DeepSeek-R1-671B（[Guo et al., 2025](https://arxiv.org/html/2509.13313#bib.bib6)）等更大的模型。

虽然 ReSum 以免训练的方式有效，但标准智能体可以进一步优化以掌握这种范例。因此，我们提出ReSum-GRPO。与监督微调不同的是，监督微调可能会覆盖一般功能并需要昂贵的专家轨迹，而我们利用强化学习（RL）的自我进化功能。该算法将经典的组相对策略优化 (GRPO)（[Shao et al., 2024](https://arxiv.org/html/2509.13313#bib.bib23)）适应 ReSum 范例。具体来说，我们在总结点对长轨迹进行分段，并利用优势广播来传播从所有分段的最终结果中获得的全局优势。这种机制有效地解决了长期任务中的信用分配挑战，鼓励智能体从压缩状态中有效推理并收集产生高质量摘要的信息。我们的主要贡献总结如下：

*•

  ReSum：即插即用范例。我们确定了广泛探索和背景限制之间的冲突。我们提出了 ReSum，这是一种范例性增强功能，可以定期将历史压缩为摘要，从而无需进行先前方法所需的架构修改即可进行无限探索。
*•

  ReSumTool-30B：专门的摘要模型。为了确保网络搜索环境中的高质量摘要，我们开发了 ReSumTool-30B。通过有针对性的训练，它擅长提取关键证据并指导未来的搜索步骤。
*•

  ReSum-GRPO：通过 RL 进行范式适应。我们设计 ReSum-GRPO 的目的是通过分割长轨迹并在所有分段中传播轨迹级优势，让智能体熟悉基于摘要的推理。对三个具有挑战性的基准进行的实验表明，与 ReAct 相比，ReSum 平均提高了 4.5%，在 ReSum-GRPO 训练后进一步提高了 8.2%。

## 2 初步

在介绍 ReSum 之前，我们回顾一下 ReAct 范式，以提供必要的背景并强调激发我们研究的基本挑战。

ReAct（[Yao 等人，2023](https://arxiv.org/html/2509.13313#bib.bib39)）是一种广泛采用的智能体工作流程（[Li 等人，2025a](https://arxiv.org/html/2509.13313#bib.bib11)；[Wu 等人，2025a](https://arxiv.org/html/2509.13313#bib.bib33)；[Li 等人， 2025c](https://arxiv.org/html/2509.13313#bib.bib13))，智能体执行思想、行动和观察的迭代循环。具体来说，在每次迭代中，LLM 基于现有上下文生成推理步骤（思想），发出可解析的工具调用（操作），并接收来自环境的反馈（观察）。在网络搜索环境中，操作空间通常由搜索查询、网页浏览或生成最终答案组成。当智能体产生最终答案时，迭代终止。具有 TT 迭代的完整轨迹可以正式定义为：

|  |  |  |
| ---| ---| ---|
|  | ℋT=(q,τ1,a1,o1,…,τT−1,aT−1,oT−1,τT,aT),\mathcal{H}\_{T}=\big(q,\tau\_{1},a\_{1},o\_{1},\ldots,\tau\_{T-1},a\_{T-1},o\_{T-1},\tau\_{T},a\_{T}\big), |  |

其中 qq 是问题，τi\tau\_{i}, aia\_{i}, 和 oio\_{i} 分别代表第 ii 轮的想法、行动和观察。在步骤 tt 中，思想 τt\tau\_{t} 和行动 ata\_{t} 都是从策略模型 πθ\pi\_{\theta} 中采样的，该模型以所有先前的上下文为 (τt,at)∼πθ(⋅∣ℋt−1)(\tau\_{t},a\_{t})\sim\pi\_{\theta}(\cdot\mid\mathcal{H}\_{t-1}).

对于具有高度模糊实体和关系的复杂网络搜索任务，智能体必须执行广泛的工具交互来收集不同的证据并集中解决方案。然而，在困难案例得到解决之前，不断附加完整的交互历史很快就会耗尽现代法学硕士的上下文窗口。为了说明这一限制，我们分析了 WebSailor-7B（[Li 等人，2025a](https://arxiv.org/html/2509.13313#bib.bib11)）在具有挑战性的 BrowseComp 基准（[Wei 等人，2025](https://arxiv.org/html/2509.13313#bib.bib32)）上的行为。如图[2](https://arxiv.org/html/2509.13313#S2.F2“图2‣2初步‣ReSum：通过上下文摘要解锁长程搜索智能”），虽然已解决的案例通常适合上下文窗口，但失败的轨迹经常超过32kk限制，需要截断。

图 2：ReAct 中的上下文限制限制了探索。我们使用 WebSailor‑7B（[Li et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib11)）在 BrowseComp（[Wei et al., 2025](https://arxiv.org/html/2509.13313#bib.bib32)）上比较正确（左）和错误（右）样本的词元消耗分布。失败的案例消耗更多的词元，这表明轨迹在解决之前经常被截断。

根据现有的网络智能体设计（[Li et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib11)；[Gao et al., 2025](https://arxiv.org/html/2509.13313#bib.bib4)；[Li et al., 2025b](https://arxiv.org/html/2509.13313#bib.bib12))，我们实现了两个用于网络探索的基本工具：搜索查询 Google 搜索引擎，接受多个同时查询并返回每个查询的前 10 个结果，Visit 使用 Jina 按 URL 浏览特定网页（[Jina.ai, 2025](https://arxiv.org/html/2509.13313#bib.bib9)），并使用Qwen2.5-72B-Instruct（[Yang et al., 2024](https://arxiv.org/html/2509.13313#bib.bib38)）提取特定目标的证据。有关 Web 智能体和智能体上下文管理的现有研究的讨论已移至附录 [A](https://arxiv.org/html/2509.13313#A1“附录 A 相关工作 ‣ ReSum：通过上下文摘要解锁长程搜索智能”）。

## 3 方法论

在本节中，我们将介绍 ReSum 范式、ReSumTool-30B 的开发以及旨在促进范式适应的 ReSum-GRPO 算法。

### 3.1 总结范式

轨迹初始化：轨迹以用户查询 qq 开始，初始化 ℋ0=(q)\mathcal{H}\_{0}=(q). ReAct 之后，智能体在内部推理和工具使用之间交替：在第 tt 轮，它在 <think> </think> 词元内生成推理步骤，并在 <tool\_call> 内发出工具调用</tool\_call>词元，表示为(τt,at)∼πθ(⋅∣ℋt−1)(\tau\_{t},a\_{t})\sim\pi\_{\theta}(\cdot\mid\mathcal{H}\_{t-1}). 系统解析工具调用参数并执行相应的工具，返回<tool\_response></tool\_response>词元内的结果为ot=ℛ⁡(at)o\_{t}=\mathcal{R}(a\_{t}),，其中ℛ\mathcal{R}代表工具环境。然后通过串联更新历史记录，如下所示：

|  |  |  |
| ---| ---| ---|
|  | ℋt=ℋt−1∘(τt,at,ot).\mathcal{H}\_{t}\,=\,\mathcal{H}\_{t-1}\circ(\tau\_{t},a\_{t},o\_{t}). |  |

在最初的几轮中，ReSum 通过迭代构建 ℋt=(q,τ1,a1,o1,…,τt,at,ot)\mathcal{H}\_{t}=\left(q,\tau\_{1},a\_{1},o\_{1},\ldots,\tau\_{t},a\_{t},o\_{t}\right). 来反映 ReAct

上下文摘要：当压缩触发器被激活时，将调用摘要工具πsum\pi\_{\text{sum}}将累积的历史记录总结为：

|  |  |  |
| ---| ---| ---|
|  | s∼πsum(⋅∣ℋt),s\sim\pi\_{\text{sum}}(\cdot\mid\mathcal{H}\_{t}), |  |

其中 ss 是一个面向目标的 <summary> </summary>，它巩固了必要的证据（附录 [C] 中提供的提示（https://arxiv.org/html/2509.13313#A3“附录 C 提示 ‣ ReSum：通过上下文摘要解锁长程搜索智能”））。然后，我们形成一个压缩状态q′=(q,s)q^{\prime}=(q,s)并将工作历史重置为：

|  |  |  |
| ---| ---| ---|
|  | ℋt←(q′).\mathcal{H}\_{t}\leftarrow(q^{\prime}). |  |

总结可以“系统地”触发，例如，达到词元限制，或由智能体“自主地”触发。在这项工作中，我们采用系统触发器来确保可预测的行为，因为可靠的自发上下文管理通常超出了当前智能体的能力。

轨迹终止：通过定期总结，ReSum 动态维护模型窗口内的上下文，同时保留必要的证据。智能体继续收集证据，一旦积累了足够的信息，就会在 <answer> </answer> 词元内生成综合答案。尽管 ReSum 理论上允许无限探索，但实际部署会施加资源预算，例如限制工具调用的数量。超过这些限制的轨迹将被终止并标记为失败。

ReSum 执行流程详见附录中的算法 [1](https://arxiv.org/html/2509.13313#alg1“算法 1 ‣ 附录 B 算法伪代码 ‣ ReSum：通过上下文摘要解锁长程搜索智能”）。通过将线性交互历史转换为可重新启动和紧凑的状态，ReSum 实现了长期探索，否则会溢出上下文窗口，同时保持与现有基于 ReAct 的智能体的功能兼容性。

### 3.2 总结工具规范

在 ReSum 中，现成的 LLM 可以作为摘要工具。然而，它的作用远远超出了传统的对话摘要。为了指导网络智能体进行持久的、面向目标的探索，摘要工具必须对冗长且嘈杂的交互历史进行逻辑推理，从大型文本片段中提取可验证的证据，并基于网络上下文提出可操作的、范围广泛的后续步骤。这些功能通常超过缺乏网络上下文推理的小型通用模型，而大型推理模型会产生令人望而却步的推理延迟和成本。为了弥补这一差距，我们通过严格的三阶段流程开发了 ReSumTool-30B。

教师模型选择：我们首先在附录[E.1]中对不同规模的模型进行了实证研究比较（https://arxiv.org/html/2509.13313#A5.SS1“E.1 上下文摘要法学硕士案例‣附录E ReSumTool-30B的补充材料‣ReSum：通过上下文摘要解锁长程搜索智能”）。我们的分析表明，推理增强模型在结构化证据合成和来源归因方面优于指令调整模型。因此，我们选择GPT-OSS-120B （[OpenAI，2025a](https://arxiv.org/html/2509.13313#bib.bib18)）作为教师模型，因为它具有长期保持目标一致性的卓越能力。

数据合成：我们通过记录 SailorFog-QA 基准上的 ReSum 轨迹来构建训练数据（[Li et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib11)），这反映了需要长期推理的具有挑战性的现实世界任务。在此设置中，我们将探索和总结角色解耦以确保质量：WebSailor 智能体充当探索者，利用其持久的信息搜索功能来导航和收集上下文，而教师模型则作为总结工具集成。此过程产生了 9,000 多对高质量的⟨Conversation,Summary⟩\langle\texttt{Conversation},\texttt{Summary}\rangle 对。

开发：利用这些收集到的对，我们将教师模型的功能提炼为Qwen3‑30B-A3B-Thinking11 1 <https://huggingface.co/Qwen/Qwen3-30B-A3B-Thinking-2507>，因其 MoE 架构而被选中，该架构可实现高效部署，同时保持强大的推理能力。由此产生的 ReSumTool-30B 展示了有效的摘要性能（附录中的图 [6](https://arxiv.org/html/2509.13313#A5.F6“图 6 ‣ E.3 ReSumTool-30B 评估 ‣ 附录 E ReSumTool-30B 的补充材料 ‣ ReSum：通过上下文摘要解锁长程搜索智能”）），附录中提供了详细的训练配置[E.2](https://arxiv.org/html/2509.13313#A5.SS2“E.2 训练配置 ‣ 附录 E ReSumTool-30B 补充材料 ‣ ReSum：通过上下文摘要解锁长程搜索智能”）。

### 3.3 总结-GRPO

ReSum 范式创建了一种新颖的查询类型q′=(q,s)q^{\prime}=(q,s)，它将原始用户查询 qq 与摘要 ss 相结合。虽然智能体可以处理此类输入，但它们最初可能会根据总结的上下文进行次优推理，因为在训练期间没有遇到这种模式。因此，我们使用强化学习来掌握这种范式。与监督微调不同，监督微调需要昂贵的专家级 ReSum 轨迹收集，并且有覆盖智能体现有技能的风险，强化学习使智能体能够通过自我进化来适应这种范式，同时保留其固有的推理能力。

轨迹分割：ReSum-RL 的关键修改是 ReSum 在进行汇总时自然地将长轨迹分割成多个片段。考虑经历 KK 汇总事件的完整 ReSum 轨迹。该轨迹自然地分为以下 K+1K+1 段：

GRPO 集成（图 [3](https://arxiv.org/html/2509.13313#S3.F3“图 3 ‣ 3.2 摘要工具规范 ‣ 3 方法论 ‣ ReSum：通过上下文摘要解锁长程搜索智能”））：ReSum‑RL 通过摘要分段仅修改 rollout 集合，并将奖励信号调整为轨迹级答案正确性。因此，它与各种 RL 算法兼容（[Schulman et al., 2017](https://arxiv.org/html/2509.13313#bib.bib22)；[Christiano et al., 2017](https://arxiv.org/html/2509.13313#bib.bib2)；[Yu et al., 2025b](https://arxiv.org/html/2509.13313#bib.bib41)）。具体来说，我们用 GRPO 实例化它（[Shao et al., 2024](https://arxiv.org/html/2509.13313#bib.bib23)），产生 ReSum-GRPO。对于初始问题 qq，我们对一组 GG 推出进行采样，每个推出 ngn\_{g} 段作为 {ℋg(i)}i=1ng\{\mathcal{H}\_{g}^{(i)}\}\_{i=1}^{n\_{g}}. 目标可以写为：

总之，ReSum-GRPO 中的优势广播机制通过以下方式实现从长程任务的所有部分进行有效学习：（1）鼓励智能体从压缩状态成功推理，（2）确保早期探索步骤在对最终成功做出贡献时获得适当的奖励。值得注意的是，ReSum-GRPO 仅通过利用分段推出来修改长轨迹，而短轨迹的处理方式与标准 GRPO 相同。这种设计不仅保持了训练效率，还保留了智能体固有的推理模式。

## 4 实验与分析

### 4.1 实验设置

基准：为了评估 ReSum 在克服复杂查询的上下文限制方面的有效性，我们在三个具有挑战性的基准上进行了实验，其中智能体通常需要进行广泛的探索：GAIA（[Mialon et al., 2023](https://arxiv.org/html/2509.13313#bib.bib17)）、BrowseComp（[Wei et al., 2025](https://arxiv.org/html/2509.13313#bib.bib32)）及其中国同行BrowseComp-zh（[Zhou et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib43)）。对于 GAIA，我们通过使用 103 个样本的纯文本验证子集来遵循现有的工作。我们排除了更简单的基准测试，例如 SimpleQA ([Wei et al., 2024](https://arxiv.org/html/2509.13313#bib.bib31))、WebWalkerQA ([Wu et al., 2025b](https://arxiv.org/html/2509.13313#bib.bib34)) 和 xBench-DeepSearch ([Xbench-Team, 2025](https://arxiv.org/html/2509.13313#bib.bib35))，大多数情况可以在标准上下文限制内解决，使 ReAct 范式更合适。

评估：遵循网络智能体研究的标准实践（[Gao et al., 2025](https://arxiv.org/html/2509.13313#bib.bib4)；[Dong et al., 2025](https://arxiv.org/html/2509.13313#bib.bib3)），我们一致使用Qwen2.5-72B-Instruct作为评分模型来评估预测答案是否与真实情况相符（参见附录 [G](https://arxiv.org/html/2509.13313#A7“附录 G 法学硕士作为法官评估的理由 ‣ ReSum：通过上下文摘要解锁长期搜索智能”）进行论证）。具体来说，我们报告了所有测试样本的平均 Pass@1，以及每个样本的三次部署的 Pass@3。除非另有说明，我们将所有推理范例的最大工具调用预算设置为 60，以确保公平比较。

基线和实施：我们在两种设置下评估 ReSum 的有效性：免培训和需要培训。在免训练设置中，我们将 ReSum 直接应用于现成的智能体，将其与 ReAct 和最近历史进行比较，即在接近上下文限制时将历史截断为最新的 22kk 标记。我们还与具有代表性的上下文管理方法MEM1（[Zhou et al., 2025b](https://arxiv.org/html/2509.13313#bib.bib44)）进行了比较。在需要训练的环境中，我们评估强化学习优化是否可以增强范式掌握。我们将 ReSum-GRPO 与标准 GRPO 和 MEM1-GRPO 进行比较。对于 ReSum 推理，当对话历史记录接近上下文限制时，始终会触发摘要，除非特别说明，否则会利用 ReSumTool-30B 进行摘要。附录 [D](https://arxiv.org/html/2509.13313#A4“附录 D 实现细节 ‣ ReSum：通过上下文摘要解锁长程搜索智能”) 中提供了更多实现细节。

### 4.2 免训练 ReSum 的性能

设置：我们评估网络智能体上的不同推理范例，包括 ReAct、Recent History、MEM1 和我们的 ReSum。所有智能体都在我们的统一推理框架下运行，并提供精心策划的提示。对于 ReSum 中的摘要工具，我们评估了四种不同规模的现成 LLM，包括 Qwen3-30B-A3B-Thinking（表示为 Qwen3-30B)、GPT-OSS-120B、Qwen3-235B 和 DeepSeek-R1-671B，以及我们开发的 ReSumTool-30B，其中以Qwen3-30B为基础。为了将性能结合起来，我们还报告了 OpenAI-o3（[OpenAI，2025b](https://arxiv.org/html/2509.13313#bib.bib19)）和 Kimi-K2（[Team et al.，2025a](https://arxiv.org/html/2509.13313#bib.bib26)）等领先预训练模型与搜索和访问工具配对的结果。定量结果如表 [1](https://arxiv.org/html/2509.13313#S4.T1“表 1 ‣ 4.1 实验设置 ‣ 4 实验和分析 ‣ ReSum：通过上下文摘要解锁长程搜索智能”）所示，揭示了以下主要发现：

ReSum 范式始终优于基线并表现出卓越的兼容性。 ReSum 展示了跨智能体和基准的性能改进，与 ReAct 相比平均绝对收益提高了 4.5%。这一增强源于 ReSum 通过智能上下文压缩保持连贯探索的能力，使智能体能够解决否则会超出上下文限制的复杂查询。虽然近期历史基线也提供了扩展的探索，但简单的截断会破坏上下文的连续性，并且无法保留用于继续推理的有价值的信息。此外，与 ReSum 相比，MEM1 在免训练环境中与现有智能体的兼容性较弱。与 ReAct 相比，直接应用 MEM1 几乎没有性能提升，在某些情况下，性能甚至会下降。这主要是由于 MEM1 的推理范式与 ReAct 的附加所有历史记录方法有很大偏差，使得在没有训练的情况下很难进行范式适应。相比之下，ReSum 保持了较高的兼容性，可以有效提升性能。

对于上下文摘要，我们开发的 ReSumTool-30B 实现了与大型模型相当的性能，同时保持了部署效率。当用作汇总工具时，ReSumTool-30B 在各个配置中始终优于其基本模型Qwen3-30B。值得注意的是，当用于汇总时，ReSumTool-30B 通常可以匹配或超过明显更大的模型的性能：在带有 WebSailor-3B 的 BrowseComp-zh 上，它实现了 13.7% Pass@1，当它们用作汇总工具时，其性能优于 Qwen3-235B (11.1%) 和 DeepSeek-R1-671B (13.0%)。这证明了我们针对性培训的有效性。

ReSum 集成使 30B 模型的性能优于多个专有基线。值得注意的是，带有 ReSumTool-30B 的 WebSailor-30B 在 BrowseComp 基准上实现了 16.0% Pass@1，超过了 Claude-4-Sonnet (12.2%) 和 Kimi-K2 (14.1%) 等强大的专有模型。虽然 OpenAI-o3 和 DeepSeek-v3.1 等前沿模型保持领先地位，但 ReSum 提供了一种经济有效的途径，可以在计算限制下增强智能体能力。

### 4.3 ReSum-GRPO 的性能

设置：我们使用 WebSailor 模型作为基础，因为它们已经经过 RFT 来获得工具调用能力，为没有 RL 经验的人提供了一个强大的起点。对于训练数据，我们从 SailorFog-QA 数据集中随机选择 1K 个样本（[Li et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib11)），因为其高质量和难度而选择。我们特意将数据规模限制为 1K，以证明我们方法的数据效率，而不是仅仅通过大量训练来追求性能极限。我们将 ReSum-GRPO 与两个基线进行比较：（1）标准 GRPO，其中轨迹按照经典的 ReAct 范式推出； (2) MEM1-GRPO（[Zhou et al., 2025b](https://arxiv.org/html/2509.13313#bib.bib44)），采用通过 GRPO 优化的 MEM1 部署流程。所有算法均使用附录 [D.2](https://arxiv.org/html/2509.13313#A4.SS2“D.2 RL 训练配置 ‣ 附录 D 实现细节 ‣ ReSum：通过上下文摘要解锁长程搜索智能”）中提供的一致超参数进行 4 个 epoch 的训练。请注意，MEM1 实验仅限于 30B 主干网络，因为较小的模型无法维持复杂的迭代范式，从而导致训练崩溃。

训练动态：平滑奖励（在 5 个步骤的窗口中平均）如图 [4](https://arxiv.org/html/2509.13313#S4.F4“图 4 ‣ 4.3 ReSum-GRPO 的性能 ‣ 4 实验和分析 ‣ ReSum：通过上下文摘要解锁长范围搜索智能”），表明 ReSum-GRPO 通常比基线获得更高的奖励。这是因为 ReSum 扩展了原本无法解决的问题的对话，以进行更多探索。随着训练的进行，ReSum-GRPO 有效地鼓励智能体熟悉这种推理模式，从而获得更高的奖励。值得注意的是，MEM1-GRPO 从最低分数开始，表明基本智能体和复杂的 MEM1 工作流程之间最初存在偏差。然而，稳定的上升趋势表明智能体通过 RL 优化逐渐与 MEM1 范式保持一致。

图 4：使用 WebSailor-30B 进行 GRPO、MEM1-GRPO 和 ReSum-GRPO 之间的训练动态比较。 ReSum-GRPO 通常会获得更高的奖励。

总体评估：在表 [2](https://arxiv.org/html/2509.13313#S4.T2“表 2 ‣ 4.1 实验设置 ‣ 4 实验和分析 ‣ ReSum：通过上下文总结解锁长程搜索智能”）中，我们根据各自的范例评估了这些 RL 训练的智能体，并将它们与强大的开源智能体进行比较，其中大多数智能体都经过 10K+ 样本的训练。我们可以得出结论：

ReSum-GRPO 对于掌握 ReSum 范式至关重要。 ReSum-GRPO 在各个基准测试中产生了显着的收益，例如，WebSailor-3B 将 BrowseComp-zh 上的 Pass@1 从 8.2% 提高到 20.5%。相反，GRPO 无法使智能体掌握摘要条件推理。虽然标准 GRPO 增强了 ReAct 推理，但它未能将这些优势转移到 ReSum 范式，这强调了特定范式优化的必要性。

ReSum-GRPO 通过高数据效率实现了具有竞争力的性能。尽管仅使用 1K 训练样本，ReSum-GRPO 使智能体能够与基于 10K 多个样本训练的强大开源模型相媲美。例如，WebSailor-30B 在 BrowseComp-zh 上达到了 33.3%，超过了 ASearcher-32B (15.6%)（[Gao et al., 2025](https://arxiv.org/html/2509.13313#bib.bib4)）、MiroThinker-32B (17.0%)（[Team et al., 2025b](https://arxiv.org/html/2509.13313#bib.bib27)) 和 WebExplorer-8B (32.0%)（[Liu 等人，2025](https://arxiv.org/html/2509.13313#bib.bib15)）。

与 MEM1 相比，ReSum 提供了性能和效率之间的平衡。虽然 MEM1-GRPO 在 BrowseComp 上实现了最高的 Pass@1，但这种边际收益的代价是高昂的计算成本。如附录 [F.3](https://arxiv.org/html/2509.13313#A6.SS3“F.3 与 MEM1 的效率比较 ‣ 附录 F 实验补充材料 ‣ ReSum：通过上下文摘要解锁长程搜索智能”) 中详细说明，MEM1-GRPO 比 ReSum 消耗近 3×\times 的词元，仅为 1.2%改善。因此，ReSum 为现实世界的部署提供了一种更实用的解决方案，保持高性能，而无需过多的迭代推理开销。

细粒度分析（附录[F](https://arxiv.org/html/2509.13313#A6“附录F实验补充材料‣ReSum：通过上下文总结解锁长程搜索智能”））：为了训练效率，ReSum-GRPO会产生更高的计算成本，因为它可以防止长轨迹的过早截断。通过定期调用摘要工具，它允许智能体从通常在标准 GRPO 中终止的扩展推理轨迹中学习。如表 [4](https://arxiv.org/html/2509.13313#A6.T4“表 4 ‣ F.1 训练效率 ‣ 附录 F 实验补充材料 ‣ ReSum：通过上下文摘要解锁长程搜索智能”) 中详细说明，这会导致大约 1.5×\times 训练时间，这是一个可管理的开销，通过性能提升证明是合理的。关于推理效率，我们将性能与资源消耗进行比较。如图所示[7(a)](https://arxiv.org/html/2509.13313#A6.F7.sf1“图7(a)‣图7‣F.2推理成本‣附录F实验补充材料‣ReSum：通过上下文摘要解锁长程搜索智能”)和[7(b)](https://arxiv.org/html/2509.13313#A6.F7.sf2“图7(b) ‣ 图 7 ‣ F.2 推理成本 ‣ 附录 F 实验补充材料 ‣ ReSum：通过上下文摘要解锁长程搜索智能”）在附录中，ReSum 范例通过合理的资源利用实现了卓越的性能。最后，我们在附录 [F.4](https://arxiv.org/html/2509.13313#A6.SS4“F.4 案例研究 ‣ 附录 F 实验补充材料 ‣ ReSum：通过上下文摘要解锁长程搜索智能”）中的定性分析表明，ReSum-GRPO 灌输了一种自适应推理策略。案例研究表明，智能体可以灵活地切换行为：它直接解决更简单的查询而无需摘要，同时正确利用摘要来执行复杂的长期任务。这表明该模型在处理更简单的任务时掌握了 ReSum 范式，同时又不失其对 ReAct 范式的熟练程度。

## 5 结论

在本文中，我们提出了 ReSum（一种通过定期总结实现无界探索的推理范式）和 ReSum-GRPO（一种用于自进化范式适应的训练算法）。实验表明，它们在免训练和需要训练的环境下处理长期信息搜索任务的有效性。未来的工作旨在从当前基于规则的外部摘要过渡到自主的、智能体驱动的机制，同时还纳入质量控制以确保摘要过程中长期依赖关系的保存。

## 附录 A 相关作品

Web 智能体：专有社区和开源社区在 Web 智能体开发方面都取得了重大进展。 DeepResearch（[OpenAI，2025](https://arxiv.org/html/2509.13313#bib.bib20)）等专有系统在复杂的网络任务中表现出色，但受到封闭架构和无法访问的训练数据的阻碍，限制了可重复性和协作研究。另一方面，开源工作主要集中在：数据合成（例如，WebSailor 和 ASearcher 中的数据模糊测试）、强化学习基础设施和算法优化（例如，专门的 ARPO（[Dong et al., 2025](https://arxiv.org/html/2509.13313#bib.bib3)））。这些进步推动系统从解决基本的多跳问答任务转向解决更复杂的信息检索挑战，例如 BrowseComp 基准测试。值得注意的版本包括 WebSailor（[Li et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib11)）、WebShaper（[Tao et al., 2025](https://arxiv.org/html/2509.13313#bib.bib25)）、ASearcher-QwQ-32B（[Gao et al., 2025](https://arxiv.org/html/2509.13313#bib.bib4))、WebExplorer-8B ([Liu et al., 2025](https://arxiv.org/html/2509.13313#bib.bib15)) 和 DeepDive-32B ([Lu et al., 2025](https://arxiv.org/html/2509.13313#bib.bib16))。尽管取得了这些成就，开源智能体仍然从根本上受到 ReAct 范式有限的探索能力的限制（[Yao et al., 2023](https://arxiv.org/html/2509.13313#bib.bib39)），这凸显了对新范式的需求。

智能体的上下文管理：基于 LLM 的智能体中最广泛使用的上下文管理方法是 ReAct 的追加所有历史策略。虽然简单，但这种方法会导致无限制的增长和快速耗尽，特别是对于复杂的查询。为了解决这些问题，一些方法引入了外部组件，例如检索模块，例如 A-MEM ([Xu et al., 2025](https://arxiv.org/html/2509.13313#bib.bib37))、MemOS ([Li et al., 2025d](https://arxiv.org/html/2509.13313#bib.bib14)) 和 ReasoningBank ([Ouyang et al., 2025](https://arxiv.org/html/2509.13313#bib.bib21))，更有效地构建上下文。然而，这些解决方案增加了大量的计算开销，增加了系统复杂性，并且与智能体松散地集成。最近的方法，例如 MEM1（[Zhou et al., 2025b](https://arxiv.org/html/2509.13313#bib.bib44)）、MemAgent（[Yu et al., 2025a](https://arxiv.org/html/2509.13313#bib.bib40)）和 MemSearcher（[Yuan et al., 2025](https://arxiv.org/html/2509.13313#bib.bib42))，允许智能体通过强化学习在内部管理上下文。这些方法通过架构修改进行创新，引入可学习的内存词元，需要从头开始对新智能体进行端到端训练，这限制了它们对现有智能体的适用性。相比之下，ReSum 为 ReAct 提供了轻量级的范例增强。这一根本区别产生了关键的实际优势，包括 (1) 免训练实用性：ReSum 无需任何训练即可提供性能提升，而 MEM1 等方法在此设置下可能会出现性能下降（表 [1](https://arxiv.org/html/2509.13313#S4.T1“表 1 ‣ 4.1 实验设置 ‣ 4 实验和分析 ‣ ReSum：通过上下文摘要解锁长程搜索智能”)）； （2）数据效率：当需要训练时，ReSum-GRPO仅使用1K样本就取得了显着的改进（表[2](https://arxiv.org/html/2509.13313#S4.T2“表2‣4.1实验设置‣4个实验和分析‣ReSum：通过上下文摘要解锁长程搜索智能”）），降低了数据成本； (3) 前向兼容性：解耦的汇总工具可以独立改进，增强所有 ReSum 兼容的智能体，而无需进行详尽的重新训练。

与世界模型增强智能体的区别：虽然 ReSum 的总结具有为（[Chae et al., 2025](https://arxiv.org/html/2509.13313#bib.bib1)）中提出的世界模型提供结构化指导的高级目标，但它们解决了根本不同的问题。世界模型专注于通过每一步的密集、前瞻性规划来提高决策质量，而 ReSum 则解决上下文窗口耗尽问题，以通过稀疏、向后看的上下文压缩来实现决策连续性。因此，ReSum 中的汇总工具充当临时上下文管理器，而不是紧密集成的规划器。

## 附录 D 实施细节

在本节中，我们将详细阐述所有推理范式和 RL 训练配置的实现细节。

### D.1 推理范式的实现

对于我们实验过的智能体，WebSailor 系列，所有智能体都受到 32kk 词元的上下文窗口的限制。我们对每个推理范式采用以下设置。请注意，对于所有推理范式，单个查询的最大工具调用预算为 60，LLM 超参数统一设置温度为 0.6，top\_p 为 0.95。

*•

  ReAct：将每个想法、行动和观察添加到对话历史记录中。在每个步骤中，我们都会监视上下文使用情况，如果智能体已到达上下文窗口但未输出答案，则作为失败终止。
*•

  最近的历史记录：每当上下文窗口达到限制时，我们就会通过仅保留最近的 22kk 消息词元来截断对话。这一策略使我们能够重新开始对话，同时为进一步探索保留额外的空间。
*•

  MEM1：与 ReAct 的追加所有历史策略不同，MEM1 维护一个恒定的上下文窗口，其中当前查询由智能体的推理、计划和上一轮的工具响应组成。然后，智能体会整合相关信息，生成内存，并发出工具调用，迭代地细化上下文以收敛于答案。对于免训练设置，我们直接将 MEM1 推理应用于网络智能体并进行及时修改。具体来说，为了确保与现有智能体的兼容性，我们将MEM1原来的特殊词元，例如<IS>、<query>替换为<think></think>和<tool\_call></tool\_call>.此外，来自先前操作的工具响应被连接到查询提示中，保留了 MEM1 的迭代结构。
*•

  ReSum：除非特别说明，我们始终将摘要触发器设置为接近上下文限制，然后调用 ReSumTool-30B 进行对话压缩。这种基于规则的汇总触发机制具有实现简单、效率高、避免频繁汇总的优点。

### D.2 RL 训练配置

我们基于 rLLM 框架实现 GRPO、MEM1-GRPO 和 ReSum-GRPO 来训练网络智能体（[Tan et al., 2025](https://arxiv.org/html/2509.13313#bib.bib24)）。对于这些 RL 算法，所有工具调用结果 oo 都被排除在损失计算之外，以防止遵循标准多轮 LLM 智能体训练实践的工具输出出现偏差（[Jin 等人，2025](https://arxiv.org/html/2509.13313#bib.bib8)；[Dong 等人，2025](https://arxiv.org/html/2509.13313#bib.bib3)）。

共享超参数：对于所有 RL 算法，由于 1K 训练样本有限，我们一致采用 batch\_size 64、组大小 GG 8、learning\_rate 2​e−62e-6 和 4 epoch。这种一致的参数设置保证了算法之间的公平比较。

算法相关设置：对于GRPO，工具调用的最大数量设置为40，总词元限制为32kk，其中为查询提示分配2kk词元，为响应分配30kk词元，包括工具调用的想法、动作和执行结果。对于 ReSum-GRPO，工具调用的最大数量增加到 60，其中为查询提示分配 4kk 词元，为响应分配 28kk 词元。当达到词元限制时，系统调用ReSumTool-30B来总结上下文，重新启动对话，并从先前的过程中收集轨迹片段。对于 MEM1-GRPO，我们遵循 MEM1 推出流程，并使用 GRPO 算法优化轨迹。此外，我们发现 MEM1 的范例很难应用于较小的模型，因为它们经常产生格式错误并且无法遵循复杂的内存整合指令。这种不兼容性扰乱了强化学习训练，阻碍了有意义的适应。因此，我们的MEM1评估仅限于更强的WebSailor-30B模型。

## 附录 G 法学硕士法官评估理由

我们决定使用基于 LLM 的评估协议，特别是使用 Qwen2.5-72B-Instruct（[Yang et al., 2024](https://arxiv.org/html/2509.13313#bib.bib38)），而不是某些基准测试提供的严格精确匹配 (EM) 脚本，例如 GAIA（[Mialon et al., 2023](https://arxiv.org/html/2509.13313#bib.bib17))，由三个关键因素证实：智能体输出的开放性、与最新文献的一致性以及判断模型的经验可靠性。

精确匹配和开放式生成之间的不匹配：GAIA 等基准测试的官方评估脚本通常依赖于严格的字符串匹配或启发式规则。这些指标通常假设模型被提示输出受限格式，例如单个数字或短语。然而，ReSum 的主要目标是实现无限制的探索和自我进化，这自然会导致智能体生成详细、合理的响应。对这些输出应用严格的 EM 会导致较高的漏报率，即智能体的答案在语义上是正确的，但由于格式差异而被拒绝。法学硕士作为法官提供了必要的语义灵活性来评估这种开放式环境中的正确性。

与现有基线保持一致：网络智能体领域最近的领先工作，包括 ASearcher（[Gao 等人，2025](https://arxiv.org/html/2509.13313#bib.bib4)）、ARPO（[Dong 等人，2025](https://arxiv.org/html/2509.13313#bib.bib3)）和 WebSailor（[Li 等人， 2025a](https://arxiv.org/html/2509.13313#bib.bib11))，已转向基于 LLM 的评估，以处理开放式网络任务的复杂性。由于我们的实验旨在针对这些开源智能体对 ReSum 进行基准测试，因此采用相同的评估协议对于确保公平和直接的可比性至关重要。

Qwen2.5-72B-Instruct作为法官的可靠性：为了确保我们选择的法官模型不会引入偏差，我们对四个候选模型进行了比较分析：Qwen2.5-72B-Instruct、GPT-4o-Mini、Qwen3-235B和Gemini-2.5-Flash。我们使用所有四位评委评估了 BrowseComp-zh 数据集上的智能体预测。结果显示出高度的一致性，模型之间的得分差异小于 0.3%。具体来说，得分为12.8%（Qwen2.5)、12.5%（GPT-4o-Mini)、12.8%（Qwen3)和12.5%（Gemini）。差异主要归因于跨语言对齐挑战，例如，将英文真实标题与中文翻译进行匹配，其中Qwen2.5在识别语义等价方面表现出卓越的能力。因此，选择Qwen2.5-72B-Instruct是因为其可靠性、与较大专有模型的高度一致性以及成本效益。
