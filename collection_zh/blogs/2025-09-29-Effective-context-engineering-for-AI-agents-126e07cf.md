在即时工程成为应用人工智能领域关注的焦点几年后，一个新术语开始受到关注：**上下文工程**。使用语言模型进行构建不再是为提示找到正确的单词和短语，而是更多地回答更广泛的问题：“什么样的上下文配置最有可能生成我们模型所需的行为？”

**上下文**是指从大语言模型 (LLM) 采样时包含的标记集。当前的**工程**问题是根据法学硕士的固有限制优化这些词元的效用，以便始终如一地实现预期结果。有效地争论法学硕士通常需要“在上下文中思考”——换句话说：考虑法学硕士在任何给定时间可用的整体状态以及该状态可能产生的潜在行为。

在这篇文章中，我们将探索上下文工程的新兴艺术，并提供一个用于构建可操纵、有效智能体的精细心理模型。

## 上下文工程与即时工程

在 Anthropic，我们将上下文工程视为即时工程的自然发展。即时工程是指编写和组织法学硕士指令以获得最佳结果的方法（有关概述和有用的即时工程策略，请参阅[我们的文档](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)）。 **上下文工程**是指在 LLM 推理期间策划和维护最佳标记（信息）集的策略集，包括提示之外可能出现的所有其他信息。

在法学硕士工程的早期，提示是人工智能工程工作的最大组成部分，因为日常聊天交互之外的大多数用例都需要针对一次性分类或文本生成任务进行优化的提示。顾名思义，提示工程的主要关注点是如何编写有效的提示，特别是系统提示。然而，随着我们朝着设计更强大的智能体、在多轮推理和更长的时间范围内运行的方向发展，我们需要管理整个上下文状态的策略（系统指令、工具、[模型上下文协议](https://modelcontextprotocol.io/docs/getting-started/intro) (MCP)、外部数据、消息历史记录等）。

在循环中运行的智能体会生成越来越多的数据，这些数据*可能*与下一轮推理相关，并且必须循环地完善这些信息。上下文工程是[艺术和科学](https://x.com/karpathy/status/1937902205765607626?lang=en)，它从不断发展的可能信息宇宙中策划进入有限上下文窗口的内容。

与编写提示的离散任务相比，上下文工程是迭代的，每次我们决定将什么传递给模型时都会发生管理阶段。

## 为什么上下文工程对于构建有能力的智能体很重要

尽管法学硕士管理越来越多的数据的速度和能力很高，但我们观察到，法学硕士和人类一样，在某个时刻会失去注意力或感到困惑。对大海捞针式基准测试的研究揭示了[上下文腐烂](https://research.trychroma.com/context-rot)的概念：随着上下文窗口中标记数量的增加，模型从上下文中准确回忆信息的能力下降。

虽然某些模型比其他模型表现出更温和的退化，但这一特征在所有模型中都存在。因此，背景必须被视为边际收益递减的有限资源。就像人类的[工作记忆容量有限](https://journals.sagepub.com/doi/abs/10.1177/0963721409359277)一样，法学硕士在解析大量上下文时也有一个“注意力预算”。每引入一个新的词元都会消耗一定数量的预算，从而增加了仔细管理法学硕士可用词元的需要。

这种注意力的稀缺源于法学硕士的架构限制。 LLM 基于[变压器架构](https://arxiv.org/abs/1706.03762)，它使每个词元能够在整个上下文中[关注所有其他词元](https://huggingface.co/blog/Esmail-AGumaan/attention-is-all-you-need)。这会产生 n 个标记的 n² 成对关系。

随着上下文长度的增加，模型捕获这些成对关系的能力就会减弱，从而在上下文大小和注意力焦点之间产生自然的张力。此外，模型根据训练数据分布发展其注意力模式，其中较短的序列通常比较长的序列更常见。这意味着模型对上下文范围依赖关系的经验较少，并且专用参数也较少。

像[位置编码插值](https://arxiv.org/pdf/2306.15595)这样的技术允许模型通过使模型适应最初训练的较小上下文来处理更长的序列，尽管在标记位置理解方面会有所退化。这些因素造成了性能梯度而不是悬崖：模型在较长上下文中仍然具有很强的能力，但与较短上下文中的性能相比，信息检索和远程推理的精度可能会降低。

这些现实意味着深思熟虑的上下文工程对于构建有能力的智能体至关重要。

## 有效情境的剖析

鉴于法学硕士受到有限的注意力预算的限制，“好的”上下文工程意味着找到“最小的”“可能的”高信号标记集，以最大化某些期望结果的可能性。实施这一实践说起来容易做起来难，但在下一节中，我们概述了这一指导原则在不同背景下的实践中的含义。

**系统提示**应该非常清晰，并使用简单、直接的语言，以“正确的高度”为座席提出想法。正确的高度是两种常见故障模式之间的金发姑娘区。在一种极端情况下，我们看到工程师在提示中硬编码复杂、脆弱的逻辑，以引发精确的智能体行为。随着时间的推移，这种方法会造成脆弱性并增加维护复杂性。在另一个极端，工程师有时会提供模糊的高级指导，无法为法学硕士提供所需输出的具体信号，或者错误地假设共享上下文。最佳高度达到了平衡：足够具体，可以有效地指导行为，但又足够灵活，可以为模型提供强大的启发式方法来指导行为。

![上下文工程过程中校准系统提示。](https://www.anthropic.com/_next/image?url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2F0442fe138158e84ffce92bed1624dd09f37ac46f-2292x1288.png&w=3840&q=75)

在这一范围的一端，我们看到脆弱的 if-else 硬编码提示，而在另一端，我们看到过于笼统或错误地假设共享上下文的提示。

我们建议将提示组织成不同的部分（例如 `<background_information>`、`<instructions>`、`## Tool guidance`、`## Output description` 等），并使用 XML 标记或 Markdown 标题等技术来描述这些部分，尽管随着模型变得更加强大，提示的精确格式可能变得不那么重要。

无论您决定如何构建系统提示，您都应该努力获得完整概述您的预期行为的最少信息集。 （请注意，最小并不一定意味着短；您仍然需要预先向智能体提供足够的信息，以确保其遵循所需的行为。）最好首先使用可用的最佳模型测试最小提示，以了解其在任务上的执行情况，然后添加明确的说明和示例，以根据初始测试期间发现的故障模式来提高性能。

**工具**允许智能体在其环境中进行操作，并在工作时引入新的附加上下文。由于工具定义了智能体及其信息/操作空间之间的契约，因此工具通过返回词元有效的信息和鼓励有效的智能体行为来提高效率非常重要。

在[为 AI 智能体编写工具 - 使用 AI 智能体](https://www.anthropic.com/engineering/writing-tools-for-agents) 中，我们讨论了构建 LLM 可以很好理解且功能重叠最小的工具。与精心设计的代码库的功能类似，工具应该是独立的，对错误具有鲁棒性，并且对其预期用途非常清晰。输入参数同样应该是描述性的、明确的，并发挥模型的固有优势。

我们看到的最常见的故障模式之一是臃肿的工具集，它们涵盖了太多的功能或导致关于使用哪个工具的决策点不明确。如果人类工程师不能明确地说出在给定情况下应该使用哪种工具，那么就不能指望人工智能智能体能做得更好。正如我们稍后将讨论的，为智能体策划一套最小可行的工具还可以在长期交互​​中实现更可靠的上下文维护和修剪。

提供示例（也称为“少量提示”）是我们继续强烈建议的众所周知的最佳实践。然而，团队经常会在提示中填入一系列边缘情况，试图阐明法学硕士在执行特定任务时应遵循的每条可能的规则。我们不推荐这样做。相反，我们建议努力策划一组多样化的规范示例，以有效地描绘智能体的预期行为。对于法学硕士来说，例子就是价值一千字的“图片”。

我们对上下文不同组成部分（系统提示**、**工具**、**示例**、**消息历史记录等）的总体指导是深思熟虑，让您的上下文内容丰富但又紧凑。现在让我们深入研究在运行时动态检索上下文。

## 上下文检索和智能体搜索

在[构建有效的人工智能智能体](https://www.anthropic.com/research/building-effective-agents)中，我们强调了基于LLM的工作流程和智能体之间的差异。自从我们写那篇文章以来，我们就倾向于为智能体提供一个[简单的定义](https://simonwillison.net/2025/Sep/18/agents/)：法学硕士在循环中自主使用工具。

与我们的客户一起工作，我们看到该领域正在向这个简单的范式靠拢。随着底层模型的能力变得更强，智能体的自主水平可以扩展：更智能的模型允许智能体独立地导航微妙的问题空间并从错误中恢复。

我们现在看到工程师在设计智能体环境时的思考方式发生了转变。如今，许多人工智能原生应用程序采用某种形式的基于嵌入的预推理时间检索来呈现重要的上下文，供智能体进行推理。随着该领域转向更智能体的方法，我们越来越多地看到团队通过“及时”上下文策略来增强这些检索系统。

使用“及时”方法构建的智能体不是预先预处理所有相关数据，而是维护轻量级标识符（文件路径、存储的查询、Web 链接等），并使用这些引用在运行时使用工具将数据动态加载到上下文中。 Anthropic 的智能体编码解决方案 [Claude Code](https://www.anthropic.com/claude-code) 使用这种方法对大型数据库执行复杂的数据分析。该模型可以编写有针对性的查询、存储结果，并利用 head 和 tail 等 Bash 命令来分析大量数据，而无需将完整的数据对象加载到上下文中。这种方法反映了人类的认知：我们通常不会记住整个信息库，而是引入外部组织和索引系统（例如文件系统、收件箱和书签）来按需检索相关信息。

除了存储效率之外，这些引用的元数据还提供了一种有效细化行为的机制，无论是明确提供的还是直观的。对于在文件系统中操作的智能体来说，`tests`文件夹中名为`test_utils.py`的文件的存在意味着与位于`src/core_logic/`中的同名文件不同的用途。文件夹层次结构、命名约定和时间戳都提供了重要信号，帮助人类和智能体了解如何以及何时使用信息。

让智能体自主导航和检索数据还可以实现渐进式披露，换句话说，允许智能体通过探索逐步发现相关上下文。每次交互都会产生上下文，为下一个决策提供信息：文件大小表明复杂性；命名约定暗示目的；时间戳可以作为相关性的智能体。智能体可以逐层组合理解，仅保留工作记忆中必要的内容，并利用笔记策略来获得额外的持久性。这种自我管理的上下文窗口使智能体专注于相关子集，而不是淹没在详尽但可能不相关的信息中。

当然，这是一个权衡：运行时探索比检索预先计算的数据慢。不仅如此，还需要有主见和深思熟虑的工程，以确保法学硕士拥有正确的工具和启发法来有效地驾驭其信息环境。如果没有适当的指导，智能体可能会因滥用工具、追逐死胡同或无法识别关键信息而浪费上下文。

在某些情况下，最有效的智能体可能会采用混合策略，预先检索一些数据以提高速度，并酌情进行进一步的自主探索。 “正确”自主级别的决策边界取决于任务。 Claude Code 是一个采用这种混合模型的智能体：[CLAUDE.md](http://claude.md) 文件被天真地放入上下文中，而像 glob 和 grep 这样的原语允许它导航其环境并及时检索文件，有效地绕过过时的索引和复杂的语法树的问题。

混合策略可能更适合动态内容较少的环境，例如法律或财务工作。随着模型能力的提高，智能体设计将趋向于让智能模型智能地行动，逐渐减少人工管理。鉴于该领域的快速进展，“做最简单、有效的事情”可能仍然是我们对 Claude 之上的团队建设智能体的最佳建议。

### 长期任务的上下文工程

长期任务要求智能体在词元计数超过 LLM 上下文窗口的操作序列中保持连贯性、上下文和目标导向的行为。对于需要持续工作数十分钟到多个小时的任务（例如大型代码库迁移或综合研究项目），智能体需要专门的技术来解决上下文窗口大小限制。

等待更大的上下文窗口似乎是一个显而易见的策略。但在可预见的未来，各种大小的上下文窗口很可能会受到上下文污染和信息相关性问题的影响——至少对于需要最强智能体性能的情况来说是这样。为了使智能体能够在较长的时间范围内有效工作，我们开发了一些直接解决这些上下文污染约束的技术：压缩、结构化笔记和多智能体架构。

#### 压实

压缩是在接近上下文窗口限制的情况下进行对话、总结其内容并使用摘要重新启动新的上下文窗口的做法。压缩通常是上下文工程中的第一个杠杆，以推动更好的长期一致性。压缩的核心是以高保真方式提取上下文窗口的内容，使智能体能够以最小的性能下降继续运行。

例如，在 Claude Code 中，我们通过将消息历史记录传递给模型来总结和压缩最关键的细节来实现这一点。该模型保留了架构决策、未解决的错误和实现细节，同时丢弃了冗余的工具输出或消息。然后，智能体可以继续使用此压缩上下文以及五个最近访问的文件。用户可以获得连续性，而不必担心上下文窗口的限制。

压缩的艺术在于选择保留什么和丢弃什么，因为过于激进的压缩可能会导致微妙但关键的上下文的丢失，而这些上下文的重要性只有在以后才会变得明显。对于实施压缩系统的工程师，我们建议仔细调整复杂智能体跟踪的提示。首先最大限度地提高召回率，以确保您的压缩提示捕获跟踪中的每条相关信息，然后进行迭代，通过消除多余的内容来提高精度。

容易悬而未决的多余内容的一个例子是清除工具调用和结果——一旦在消息历史记录的深处调用了一个工具，为什么智能体需要再次查看原始结果？最安全、最轻量级的压缩形式之一是工具结果清除，最近作为[Claude 开发者平台上的功能](https://www.anthropic.com/news/context-management) 推出。

#### 结构化笔记

结构化笔记或智能体记忆是一种技术，智能体定期将笔记写入上下文窗口之外的内存中。这些注释稍后会被拉回到上下文窗口中。

此策略以最小的开销提供持久内存。就像 Claude Code 创建待办事项列表或自定义智能体维护 NOTES.md 文件一样，这种简单的模式允许智能体跟踪复杂任务的进度，维护关键上下文和依赖关系，否则这些上下文和依赖关系可能会在数十个工具调用中丢失。

[Claude 玩 Pokémon](https://www.twitch.tv/claudeplayspokemon) 演示了内存如何在非编码域中转换智能体能力。该智能体在数千个游戏步骤中保持精确的统计，跟踪目标，例如“在我在 1 号公路上训练我的神奇宝贝的最后 1,234 步中，皮卡丘已经提升了 8 级，朝着 10 级的目标迈进。”在没有任何关于记忆结构的提示的情况下，它会开发已探索区域的地图，记住它已解锁的关键成就，并保留战斗策略的战略记录，以帮助它了解哪些攻击最适合对付不同的对手。

上下文重置后，智能体会读取自己的笔记并继续进行数小时的训练序列或地下城探索。总结步骤之间的这种一致性使得长期策略成为可能，而如果将所有信息单独保留在法学硕士的上下文窗口中，这是不可能实现的。

作为[Sonnet 4.5 发布](https://www.anthropic.com/effective-context-engineering-for-ai-agents) 的一部分，我们在 Claude 开发者平台上发布了公开测试版的[记忆工具](http://anthropic.com/news/context-management)，该工具可以让您更轻松地通过基于文件的系统在上下文窗口之外存储和查询信息。这使得智能体能够随着时间的推移建立知识库，跨会话维护项目状态，并参考以前的工作，而无需将所有内容都放在上下文中。

#### 子智能体架构

子智能体架构提供了另一种绕过上下文限制的方法。专门的子智能体可以使用干净的上下文窗口来处理重点任务，而不是由一个智能体尝试维护整个项目的状态。主智能体负责协调高层计划，而子智能体则执行深入的技术工作或使用工具查找相关信息。每个子智能体可能会使用数万个或更多词元进行广泛探索，但仅返回其工作的浓缩、提炼摘要（通常为 1,000-2,000 个词元）。

这种方法实现了清晰的关注点分离——详细的搜索上下文在子智能体内保持隔离，而主导智能体则专注于综合和分析结果。 [我们如何构建多智能体研究系统](https://www.anthropic.com/engineering/multi-agent-research-system) 中讨论的这种模式在复杂的研究任务上比单智能体系统有了显着的改进。

这些方法之间的选择取决于任务特征。例如：

* 压缩可维持需要大量来回的任务的对话流程；
* 记笔记非常适合具有明确里程碑的迭代开发；
* 多智能体架构可处理复杂的研究和分析，其中并行探索会带来好处。

即使模型不断改进，在扩展交互中保持一致性的挑战仍然是构建更有效智能体的核心。

## 结论

上下文工程代表了我们如何利用法学硕士进行构建的根本性转变。随着模型变得更加强大，面临的挑战不仅仅是精心设计完美的提示，而是在每个步骤中精心策划哪些信息进入模型有限的注意力预算。无论您是为长期任务实施压缩、设计词元有效的工具，还是使智能体能够及时探索其环境，指导原则都是相同的：找到最小的高信号词元集，以最大限度地提高您期望结果的可能性。

我们概述的技术将随着模型的改进而不断发展。我们已经看到，更智能的模型需要更少的规范性工程，从而使智能体能够拥有更多的自主权。但即使随着能力的扩展，将上下文视为宝贵的、有限的资源仍然是构建可靠、有效的智能体的核心。
